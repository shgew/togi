# Rust as the implementation language

Status: Accepted.

Supersedes [ADR 0001](0001-go.md) for the language. [ADR 0001](0001-go.md) chose Go for fast compiles, cached test results, one formatter and simple Nix packaging, and named Rust's exhaustive enums as what it gave up. The owner decided on 2026-10-10 to move togi to Rust ([#634](https://github.com/shgew/togi/issues/634)). The migration runs as the stages listed there; [`docs/porting.md`](../porting.md) holds its rules and [`docs/rust-migration.md`](../rust-migration.md) its log.

## Decision

togi is rewritten in Rust, for three reasons:

- **Correctness in the types.** Event kinds, phases and decisions become enums the compiler checks exhaustively; an SMU write cannot compile without a durable `smu.intent`; safe Rust has no data races.
- **Memory and garbage collection, measured.** In a heavy simulated session (`flat-hazard`, seed 102, 217,192 events), background garbage collection took about 30% of user CPU (2.24 s against 1.57 s with `GOGC=off`), and the process peaked at 405 MB. A probe ([`rust-probe`](https://github.com/shgew/togi/tree/rust-probe/prototype/rustprobe), commit 4b20b151) ported the hottest allocating path (simulated samples → `sampleEvidence` → `requests.Summarize`) over all 30,177 trials of that session, with byte-identical output from every variant. Mean wall time over 10 runs: Go as on `main` 4.21 s; Go without per-sample allocation 0.47 s; Rust without per-sample allocation 0.31 s; a straight Rust port with std `HashMap` 2.50 s. Design dominates, and [#629](https://github.com/shgew/togi/issues/629) took the Go fix; the language adds about 1.5× and halves peak memory on that path (12.0 MB against 5.4 MB).
- **A Rust workflow for agent-driven development.** The owner expects Rust to suit agents better. Published evidence for that is thin, so the migration records what it costs and what it catches in `docs/rust-migration.md`.

**The language changes, the behavior does not.** The `tuner.Ruleset`, journal schema 4, the config format and the CLI surface stay the same, and the session on the target machine continues across the cutover without a reset. Before the cutover, the Rust build writes journals byte-identical to Go's on all 252 suite sessions, ignoring only build stamps. `status`, `events` and `doctor` output, the stdout/stderr split and exit codes stay identical, and dashboard frames stay identical cell by cell, text and style. Only `--help` text and shell completions may change, to clap's generated output, reviewed once at the cutover. A decision or format change never lands in a porting pull request: it lands in Go before the freeze or in Rust after the cutover.

**Rust-native from the first crate.** Porting pull requests may change structure, never behavior. A Cargo workspace sits in this repository beside the Go module with no FFI between the languages; crates merge to `main` one at a time once their comparison against Go passes, and the shipped binary stays Go until the cutover pull request. From the moment stage 2 builds the Go-vs-Rust comparison, its assets (the Go reference, golden files, fixture journals, `just same` and the CI comparison job) change only in pull requests the owner approves; before that, Go pull requests implementing decided issues update goldens, baselines and machine files as those issues require. [ADR 0003](0003-journal-is-source-of-truth.md) stands: the journal remains the source of truth, which is what makes the byte comparison possible.

## Considered Options

- **Stay in Go with the allocation fixes:** the probe showed that design, not language, removes most of the cost, and #629 applies that fix in Go. Rejected: it keeps the string- and integer-typed kinds the compiler cannot check, and leaves the remaining 1.5× and the doubled peak memory on the table.
- **A verbatim port, refactored afterwards:** rejected. The probe's straight port with std `HashMap` ran at 2.50 s against 0.31 s for the Rust-native version, and a verbatim port carries Go's shape (payload structs and a registry, `map[int]…` plus sorting, wrapped errors) into code that would then need a second, riskier rewrite.
- **A Go↔Rust FFI bridge, porting from the inside out:** rejected. Turborepo found its cross-language bridge the main cost of its migration; togi's byte comparison of whole journals makes a parallel implementation compared in CI cheaper and stronger.
- **One long branch merged at once:** rejected. It defers every comparison failure to one large review and diverges from Go bugfixes landing meanwhile.
- **A stack of dependent pull requests:** rejected. Each crate merges on its own once its comparison passes; a stack would restack and re-review every layer above each fix.

## Consequences

ADR 0001's reasons for Go no longer decide the language. Compile and test times are measured from the pilot on and recorded next to Go's in the migration log; the toolchain choices that depend on them (a nightly dev shell, `sccache`, a build cap per host) are adopted only on a clear gain. Go stays in the dev shell until the Go tools rewritten in nushell have landed. `GLOSSARY.md` terms, specs and ADRs keep their meaning; the Go-specific parts of AGENTS.md and the specs are rewritten after the cutover.
