# Bench verdicts rest on fitted machines

Decision 4 and the rule that a kept tuner experiment keeps the target fits passing the model check are amended by [ADR 0044](0044-write-flagged-target-fits.md): when the all-facts fit itself fails the model check, `just fit` writes flagged bootstrap refits unconstrained and names every member's flagged groups in its header and the report, and a kept experiment needs target model checks unchanged from setup. Decision 3 and the check are unchanged.

## Context

The bench compares tuner strategies by simulated time to conclusion, with guards against losing conclusion, depth or final-profile safety. Hand-written adversarial machines are useful for testing known failure shapes, but a win on them is not enough to claim a win on the target machine. The former `shared-rail.toml` modeled a CCD0 joint and missed the target machine's CCD1 R7 joint.

The target evidence now available spans five same-BIOS sessions, 2,896 decisive starts and about 113 hours of measured trial outcomes, including seven CCD1-only R7 failures. Earlier evaluation left much of this evidence unused, including outcomes from before `reset --all` and older builds. These are measured trial hours, not elapsed session hours; pooled outcomes alone are not per-offset failure probabilities. The fitted files now contain R7 joints on both CCDs.

A tuner changes which profiles and classes it visits. Exact replay can anchor known observations but cannot answer every new trial. A single fitted machine supplies those missing answers, yet sparse observations and correlated trial evidence leave uncertainty in its parameters. Proof therefore needs a checked fallback ensemble as well as direct real-fact replay, without letting the tuner inspect either.

## Decision

1. **Keep the bench metric.** Compare simulated hours to the first clean qualifying rotation supporting a done, fully refined profile, including simulated crash-reboot time. Preserve V1–V3 and use `target` for V4: the target replay-oracle ensemble must not get slower overall. Qualification, not a durability tier, defines conclusion after ADR 0028.
2. **Use all same-BIOS evidence.** Extract archived and live decisive facts through `internal/facts`, including older builds and sessions before a reset. Commit a privacy-safe, reproducible extract retaining class, full profile, outcome, duration and provenance. Evaluation does not use the tuner's evidence-eligibility rules to discard those observations. BIOS context still limits fitting, checking and replay.
3. **Check machine files against the extract.** Group decisive starts by BIOS context, trial class and shallowest loaded-core offset. For groups with at least ten starts, compare observed failures with the unchanged inclusive 99% binomial interval computed from the simulator's mean predicted per-start failure probability over intended durations. Count trial-less idle failures separately, without inventing an exposure denominator. `just bench` reports flags and records eligible groups; a flagged target member cannot support a target-machine improvement claim even though the numeric verdict and exit status do not enforce that condition.
4. **Fit an ensemble.** `just fit` produces an all-facts fit and eight whole-trial bootstrap refits. Fit the Bernoulli likelihood using the same failure-probability calculation as the check, including per-core edges, supported workload effects and CCD R7 joints. Check every serialized member against the original extract. When an unconstrained refit is flagged, restart from the passing all-facts fit and optimize the same resampled likelihood subject to every original group's unchanged interval. Report the constraint; do not redraw samples or relax the check. This is a checked, constrained bootstrap ensemble, not an unconstrained confidence interval.
5. **Replay matching real facts, fit the rest.** The `target` scenario replaces `shared-rail` and distributes each split's seeds across `target-fit-0.toml` through `target-fit-8.toml`. At an exact full-profile and class match in the same BIOS context, the oracle draws uniformly from matching decisive outcomes, deterministically per seed and trial ID/index. Condition, phase, source ruleset and evidence epoch do not limit the match. Other trials and trial-less failures use the selected fitted member. Only ordinary journal evidence reaches the tuner. Verdict rows report `real_answer_share` for candidate and baseline so readers can see how much of each path used direct real outcomes.

A kept tuner experiment must win the bench, preserve every guardrail and keep the target fits passing the model check. The simulator, facts, machines, suite and baseline are frozen during research. After new hardware runs, refreshing the extract with `just facts COPY-OF-STATE-DIR`, refitting and recording a new baseline are separate owner-triggered evaluation changes.

The [research program](../../tools/bench/program.md) branches from `main` and compares against `tools/bench/baseline.jsonl`, recorded with `just bench-baseline` on the ruleset-7 tuner and the oracle suite, and recorded again whenever the tuner on `main`, the suite, the facts or the fitted machines change; baselines from before the oracle cannot prove V4. Agents analyze and open pull requests for kept work, with one ruleset bump when decision changes become pull requests. The owner merges every pull request and deploys manually.

## Considered Options

- **Hand-written machine files only:** rejected for target claims. They encode the author's assumptions and missed a real CCD1 failure shape. Keep synthetic adversarial scenarios for hazards the target evidence may not expose.
- **Replay only, without a fitted fallback:** rejected. Exact matches are sparse, and a changed tuner visits new profiles, classes and durations. Restricting experiments to historical paths would prevent measuring those changes; inventing an answer would hide the missing evidence.
- **A single fit without an ensemble:** rejected. One optimum makes a strategy's apparent benefit depend on one parameter choice. Whole-trial refits expose some sensitivity while checks against the original observations keep each fallback consistent with eligible evidence groups.
- **An unchecked bootstrap ensemble:** rejected. Sparse failures can disappear from a resample and produce a fallback that contradicts an observed group. Preserve each sampled likelihood while constraining the refit to the original check, and disclose which refits needed it.

## Consequences

A bench win is now evidence about a fixed checked ensemble and replay coverage, not just a hand-written approximation. The oracle preserves directly observed outcomes where available; the fitted fallback makes new paths runnable. Model checks and replay remain development tooling, not new runtime decisions or access to hidden machine information for the tuner.

This proof remains conditional. Adaptive starts are not independent trials merely because the check uses a binomial interval, and per-group intervals do not promise joint 99% coverage. Bootstrap constraints truncate the ensemble's spread. Unsupported boundaries and failure-time shapes remain unidentified; idle facts without exposure cannot identify idle rates. Hazard metrics describe the fitted fallback rather than an empirical oracle hazard. `real_answer_share` measures coverage, not confidence, and it can change when the tuner takes a different path.

Evidence refreshes require reviewing the extract, fitting and checking every member, then recording a fresh baseline. Keeping that environment frozen prevents an experiment from improving its score by weakening the model. The program separates experimental decisions from owner-controlled evaluation updates, merges and hardware deployment. It adds no runnable behavior; [benchmarking](../benchmarking.md) documents the tooling and its limits.
