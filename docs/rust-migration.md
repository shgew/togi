# Rust migration log

The log of the move from Go to Rust ([#634](https://github.com/shgew/togi/issues/634), [ADR 0048](adr/0048-rust.md)). The rules are in [`porting.md`](porting.md), and the contract is [ADR 0058](adr/0058-native-rust-rewrite.md). Every stage appends an entry for what its pull requests measured and found: dates, lines removed and added, compile and test times next to Go's, regressions, review findings, and agent cost where known. Stage 12 ([#647](https://github.com/shgew/togi/issues/647)) turns this file into a retrospective.

Append entries below the last one, newest last. State what was measured and how, and name what was not measured.

## Stage 0: the probe (2026-10-10)

**Question.** Is Rust worth porting togi for, and how much of the cost in a heavy simulated session is the language rather than the code's design?

**Setup.** Branch [`rust-probe`](https://github.com/shgew/togi/tree/rust-probe/prototype/rustprobe), commit 4b20b151, `prototype/rustprobe/`. It is throwaway and never merges. It ports the hottest allocating path of a simulated session: simulated trial conditions → `session.sampleEvidence` → `requests.Summarize`. The input is all 30,177 trials listed in `trials.tsv`, drawn from the `flat-hazard` session at seed 102 (217,192 journal events). Five variants produce byte-identical output; hyperfine ran each for 10 runs.

- `go-verbatim`: the Go code as on `main` at the time, a fresh map per sample.
- `go-tuned`: the same logic without per-sample allocation.
- `rust-verbatim-std`: a straight port of `go-verbatim` with std `HashMap`.
- `rust-verbatim-fx`: the same port with the Fx hasher.
- `rust-tuned`: mirrors `go-tuned` line for line.

**Code size.** The probe adds 609 lines in its Go implementation and 653 in its Rust implementation, containing both verbatim and tuned variants; it removes no production code. This is an experiment's size, not a production port's reduction.

**Session profile on `main`** (the profile that picked the path): background garbage collection took about 30% of user CPU, 2.24 s against 1.57 s with `GOGC=off`, and the process peaked at 405 MB.

**Results** (`single.md`; peak memory is the largest `memory_usage_byte` of the 10 runs):

| Variant | Mean wall [s] | Min [s] | Max [s] | Relative | Peak memory [MB] |
|:---|---:|---:|---:|---:|---:|
| `go-verbatim` | 4.209 ± 0.219 | 3.991 | 4.501 | 13.80 ± 0.77 | 14.8 |
| `rust-verbatim-std` | 2.495 ± 0.038 | 2.463 | 2.598 | 8.18 ± 0.21 | 5.7 |
| `rust-verbatim-fx` | 1.258 ± 0.100 | 1.184 | 1.411 | 4.12 ± 0.34 | 5.3 |
| `go-tuned` | 0.469 ± 0.014 | 0.457 | 0.503 | 1.54 ± 0.06 | 12.0 |
| `rust-tuned` | 0.305 ± 0.006 | 0.300 | 0.320 | 1.00 | 5.4 |

**Findings.**

- Design dominates. Removing the per-sample allocation took Go from 4.21 s to 0.47 s, 9×. [#629](https://github.com/shgew/togi/issues/629) applied that fix to the Go code (PR [#648](https://github.com/shgew/togi/pull/648)): on the same session, user CPU fell from 2.48 s to 1.87 s and total allocation from 2.49 GB to 1.25 GB, with every journal and `samples.jsonl` byte-identical.
- The language adds about 1.5× (`go-tuned` 0.469 s against `rust-tuned` 0.305 s) and about half the peak memory on this path.
- A straight Rust port is not fast by itself: with std `HashMap` it took 2.50 s, 8× the Rust-native version. The decision to port Rust-native rather than verbatim (ADR 0048) rests on this.
- Rust is not free of the same design flaw: swapping the hasher alone halved the verbatim port's time, which is why dense per-core arrays replace `map[int]…` in the port guide.

**Limits.** One path, one session and one build of each language. It measures wall time and peak memory of that kernel, not compile time, test time, the effect on agent-driven development, or a whole-session Rust comparison. Comparison failures, regressions, independent review findings and agent cost were not recorded for the probe. The pilot (stage 2, [#637](https://github.com/shgew/togi/issues/637)) records compile and test times against Go's.

**Decisions.** The owner decided on 2026-10-10 to migrate ([#634](https://github.com/shgew/togi/issues/634)), and that agents merge migration pull requests once CI and the `review` check pass and every thread is resolved, except the cutover and changes to the protected comparison assets. The same day, the Go structure-only issues the port replaces were closed ([#104](https://github.com/shgew/togi/issues/104), [#124](https://github.com/shgew/togi/issues/124), [#321](https://github.com/shgew/togi/issues/321), [#322](https://github.com/shgew/togi/issues/322), [#323](https://github.com/shgew/togi/issues/323), [#550](https://github.com/shgew/togi/issues/550), [#552](https://github.com/shgew/togi/issues/552), [#562](https://github.com/shgew/togi/issues/562), [#565](https://github.com/shgew/togi/issues/565) to [#568](https://github.com/shgew/togi/issues/568), [#573](https://github.com/shgew/togi/issues/573), [#575](https://github.com/shgew/togi/issues/575), [#577](https://github.com/shgew/togi/issues/577)) and [#541](https://github.com/shgew/togi/issues/541)'s type cut was superseded; their designs are in the porting guide.

## Stage 2: the start and the reversal (2026-10-11)

The owner started stage 2 ([#637](https://github.com/shgew/togi/issues/637)) on 2026-10-11 under [ADR 0057](adr/0057-running-the-rust-migration-unattended.md). Its crates then matched Go: `togi-version` ([#696](https://github.com/shgew/togi/issues/696)), `togi-trialfiles` ([#695](https://github.com/shgew/togi/issues/695)), `togi-machine` ([#703](https://github.com/shgew/togi/issues/703)) and `togi-requests` ([#704](https://github.com/shgew/togi/issues/704)) landed, and a Go-compatibility crate with its vector generator, a comparison harness and a guard were built around them.

The same day the owner reversed the contract ([#737](https://github.com/shgew/togi/issues/737), [ADR 0058](adr/0058-native-rust-rewrite.md)): the port is native, journals and state are not compatible with Go's, and a Go bug found while porting is fixed in the port. The Go-compatibility crate, the vector generator, the comparison harness and the guard were deleted, and nothing they measured is carried forward. `togi-trialfiles` and `togi-machine` were rewritten on flate2, std errors and serde defaults. The four entries below record the surviving crates as they first landed; the native rewrite entry after them records what changed.

## Stage 2: the root package (2026-10-11)

The `togi-version` crate ports `version.go` ([#696](https://github.com/shgew/togi/issues/696)): 33 lines of library and 32 of tests against Go's 48 and 84, with the Go package unchanged. `version()` is the trimmed `version.txt`, embedded at compile time; `rev()` is the `TOGI_REV` the build sets at compile time, which plays the part of Go's `-X github.com/shgew/togi.rev`; `string()` joins them with `+`.

- **Departure from Go, the owner's call.** A local cargo build reports `dev`. Go reads the commit and dirty flag from the build's VCS settings, which cargo does not record, so that branch has no port; `bench` and `forecast` read the commit from git at run time instead (#637, Version stamps).
- **Not yet stamped.** The flake builds no Rust package until the binary lands (stage 7), so nothing sets `TOGI_REV` yet; that package's derivation sets it from the flake revision as `packages.default` does for Go.
- **Not measured yet.** Compile and test times wait for the stage's measurements pull request.

## Stage 2: `internal/trialfiles` (2026-10-11)

The `togi-trialfiles` crate ports `internal/trialfiles` ([#695](https://github.com/shgew/togi/issues/695)): 1,923 lines of library and 1,555 of tests against Go's 140 and 295, with the Go package unchanged. Most of the library is not the port itself: `goerr.rs` holds Go's errno tables, `goos.rs` Go's `os.Remove`, `Rename`, `ReadDir` and checked close, and `gzip.rs` with its `flate` module Go's `gzip.Reader` and `compress/flate` decompressor (including `flate: corrupt input before offset N` and the bytes delivered before an error), so that the errors `Compress` writes verbatim into the journal (`session.warning.error`) and `Open`'s header errors read as Go's do. It removes the placeholder crate and the `--no-tests=pass` flags the empty workspace needed.

- **One departure from Go: the compressed bytes.** `Compress` writes the same gzip container, with Go's default header (`1f 8b 08 00 00 00 00 00 00 ff`), but flate2's DEFLATE encoder chooses different blocks than Go's `compress/gzip`, so the same input compresses to different bytes. No spec, comparison (`tools/bench/same.go` skips trial directories), golden file or consumer depends on those bytes; the spec freezes the gzip container and the decompressed content.
- **Dependencies this crate introduces.** `flate2` with its pure-Rust `miniz_oxide` backend, because std has no DEFLATE: it supplies the compressor and the CRC-32. Its decoders are not used, because they differ from Go's observably (a stream decoder can drop already decoded bytes when it meets corrupt data, where Go hands them over before the error), so the decoder is the port above. `nix` as a safe wrapper where rustix has no safe API: the checked close (rustix's `close` is `unsafe`, std's `File` drops the close error, and `unsafe_code` is denied here) and `mkfifo` for the tests on Apple. `rustix` for `unlink`, `rmdir`, `rename` and the open flags; `thiserror` for the error enums.
- **Go's error text.** `goerr.rs` renders each failure like the `*os.PathError` or `*os.LinkError` Go returns (`op path: errno text`, the ops Go uses at each call), with the errno strings of Go's tables for Linux (amd64 and arm64, which differ only by errno 133) and Apple, `errno N` for an unknown one, and paths as `filepath.Join` cleans them, and `invalid argument` for a path with an embedded NUL. The errors keep Go's raw path bytes, because a workload chooses its directory names and Go's JSON encoder writes each invalid byte as the literal U+FFFD character, the same bytes a real U+FFFD becomes: `go_text()` on `Error` and `Errors` returns Go's exact `err.Error()` bytes for the journal encoder to serialize with Go's JSON rules, while `Display` shows each invalid byte as the character U+FFFD. It moves to `togi-gocompat` when a second crate needs it. `Remove` also removes an empty directory, and `Rename` refuses to replace a directory (EEXIST), as Go's `os` does; `ReadDir` skips an entry that vanished before its type lookup.
- **Not measured yet.** Compile and test times wait for the stage's measurements pull request.

## Stage 2: `internal/machine` (2026-10-11)

The `togi-machine` crate ports the shared vocabulary, dense per-core readings, workload catalogue, diagnostic sample reader and synchronous machine seams ([#703](https://github.com/shgew/togi/issues/703)): 1,819 lines of library and 1,398 of tests, against Go’s 615 and 346 excluding the schedule. No Go code is removed or changed. The later journal, requests, simulator, session, SMU and trial crates consume these types; this crate does not yet drive a simulated session.

- **Offset types.** `TargetOffset::new` validates [-50, 0]; `TargetOffset::clamped` preserves the explicit Go clamps. `ObservedOffset` carries any signed 64-bit readback, baseline or decoded journal offset, including +10 and values below -50, and encodes as a JSON integer. The nine production clamp expressions are the driver’s per-core and all-core setters (`internal/smu/driver.go:100,114`), the session’s starting candidate and restoration (`internal/session/session.go:1060,1455`), reset’s starting candidate (`internal/tuner/reset.go:46`) and the four generated simulator limit expressions (`internal/sim/sim.go:483,487,489,490`). The tuner also has one-sided bounds in `search.go:40,58,144` and `constraints.go:91`; those remain distinct from constructor validation.
- **Shape choices not fixed by the plan.** Core IDs have checked constructors; CCD and logical CPU IDs are separate signed newtypes. Unknown MCE attribution is `None`, corresponding to Go’s core -1, rather than an invented supported core. Vocabulary enums keep an `Unknown` variant so permissive journal values survive; it wraps a type whose only constructor is the normalizing `From`, so a named or empty string has one value, as in Go, and explicit empty variants distinguish no signal or reset reason from the named unknown reason. Workloads live in static arrays and catalogue reads allocate nothing. `NanoDuration(i64)` preserves signed Go durations; `jiff::Timestamp` carries wall time. Cancellation is std-only (`Arc`, `AtomicBool`, `Mutex`, `Condvar`): clones share cancellation, child tokens inherit it without cancelling their parent, and waits need neither a runtime nor polling. Stage 5 bridges this token inside its async adapters; no Tokio dependency reaches machine. `HostText` keeps raw host/kernel bytes, replacing each invalid UTF-8 byte individually when comparing BIOS context and and writing each invalid byte as the literal U+FFFD character when encoding JSON, as Go’s encoder does (there is no escaped form). One string writer serves `HostText` and the vocabulary types.
- **Ownership.** Machine owns its seam adapters. Reporter callbacks borrow a non-`Send` trait object on the waiting thread; implementations must join before returning from wait, and stop must join and retain its first result. The SMU seam keeps separate read, per-core write and all-core write methods; only reads return raw observed offsets. Both write methods now have active Clippy tripwires. A separate throwaway caller failed on both forbidden methods as intended.
- **Diagnostic samples.** The reader uses `togi-trialfiles` for plain-first and gzip behavior, yields complete valid lines only, ignores undecodable lines, discards torn tails and closes on early iterator drop. Decoding retains Go’s null handling, duplicate-field updates, case folding, unsupported-core rejection, short/long fixed-array handling and invalid-string replacement. `json_text` is the one entry point that turns bytes Go wrote into text serde decodes as Go does (invalid bytes and unpaired surrogates become U+FFFD, nesting beyond 10000 levels is an error); `ReadSamples` and the journal use it, and one struct-decoding helper serves `TrialConditions`, `PmTable`, `CoreInfo`, `BiosContext` and `PstoreRecord`. PM-table numbers parse directly as `f32`, avoiding an `f64` intermediate; a midpoint-adjacent input pins the double-rounding hazard.
- **Precisely deferred to stage 4.** As #637 and #639 specify, `loadsteps.go`, `TestLoadSchedule` and `Started.Schedule` land together with PCG. `PmTable` and `TrialConditions` intentionally have no general-purpose serialization implementation: their Go writers live in `internal/sim/samples.go` and `internal/trial/samples.go`. Before the simulator writes samples, #639’s float32 acceptance requires Go-generated bit-width-32 vectors and `togi-gocompat` formatting whose shortest digits and exponent thresholds are evaluated at that width; then the sample encoder must use it for all six PM-table arrays and `json_f64` for package power, preserve field order and Go’s omission rules, and never fall back to Serde’s float formatter.
- **Tests and findings.** All eleven in-scope Go tests have named Rust equivalents; the PR records their map and the excluded schedule test. Additional properties cover all signed offset inputs, sparse per-core JSON round trips and unknown vocabulary strings; real-thread tests cover shared and child cancellation and waking waiters without sleeps. Tests caught an external `io::Error` wrapper hiding its joined inner sentinels from a plain source-chain walk; classification now inspects the retained inner error, and the regression passes. The gate rejected a path-only workspace dependency as a wildcard; the dependency now also declares the internal crate’s version. The PR attaches the changed-line coverage output, including #733’s false “not built” classification of the module-only `lib.rs`. Debug and release tests, host and aarch64 macOS Clippy, and the target-constructor compile-fail doctest passed.
- **Review findings fixed.** Invalid host bytes were written as the escape `\ufffd` where Go writes the literal U+FFFD; vocabulary strings skipped Go’s escaping of U+2028/U+2029 and `<>&`; `Unknown` could hold a named or empty string; invalid UTF-8, unpaired surrogate escapes and the 10000-level nesting limit were not Go’s at the decoding boundary; duplicate PM-table arrays erased readings under `null` elements; `CoreInfo`, `BiosContext`, the ID types and `PstoreRecord` decoded with derived Serde instead of Go’s struct rules (folding, duplicates, `null`, and a later array reusing an earlier one’s elements); and the property tests used a random seed. A second review found that routing vocabulary serialization through `RawValue` made every vocabulary type fail as a JSON map key, which Go’s simulator maps use; it now writes a plain string whenever serde’s bytes equal Go’s and errors otherwise. Each fix has Go 1.27.1-generated vectors.
- **Not measured.** Isolated compile/test times against Go, whole-session comparison cost, independent review findings and agent cost are not measured here; the stage’s measurements and the first consuming crates provide those records. No behavior regression or change to a protected Go/comparison asset is intended.

## Stage 2: `internal/requests` (#704, 2026-10-11)

The `togi-requests` crate ports `internal/requests` ([#704](https://github.com/shgew/togi/issues/704)) with the Go package unchanged. `summarize`, `groups`, `counts` and `top` keep Go's statement order and arithmetic, and the package reads and writes no files, so no path, mode or `os` error text is involved.

- **Types.** Loaded cores are `CoreId`, CCDs are `CcdId`, and `Telemetry` holds `PerCore<f64>`, `Vec<CoreId>` and `BTreeMap<CcdId, i64>`. Go's nil and empty collections are one value here: `summarize` returns `None` where Go returned `false` with the zero `Telemetry`, and a `Some` always holds at least one request, one top requester and an optional, possibly empty, CCD map. Go's out-of-range core check cannot arise: a core outside 0–15 never reaches the crate, because its caller cannot build a `CoreId` from it.
- **Early exit.** Go's `Summarize` returns as soon as a core is out of range or the samples run out, leaving its caller's iterator to drain; the Rust function takes an `IntoIterator` and drops it on return, so a caller that must see every sample passes `&mut iterator` or wraps it.
- **Duplicate cores.** A core listed twice is appended twice per sample, as in Go, so it counts twice in its CCD's clock median.
- **Tests.** The six Go tests, with the four `TestGroups` cases as one table, map to `summarize_uses_samples_after_warmup`, `summarize_needs_min_samples_after_warmup`, `summarize_needs_min_clock_samples_per_ccd`, `summarize_skips_samples_without_lanes`, `groups_orders_by_request` and `counts_raises_a_request_by_whole_counts`. Added: no cores, a repeated core, NaN and signed zero in `groups` and `top`, the empty `top`, and the boundary of the comparator (`compare_orders_nan_first_and_signed_zeros_equal`).

## Stage 2: native rewrite of `togi-trialfiles` and `togi-machine`, `togi-requests` adapted (#737, 2026-10-11)

- **`togi-trialfiles`** reads and writes gzip with flate2 (`MultiGzDecoder` and `GzEncoder`) and reports std `io::Error`s that name the path. It keeps what the crate is for: compression writes the `.gz` whole under a temporary name, syncs it, renames it into place and only then removes the plain file, so a reader finds one complete form at every moment; a symlinked log or instance directory is never followed; `open` prefers the plain file and falls back to the compressed one. Its ported gzip and DEFLATE readers, Go errno tables and Go `os` behaviors are gone, with the tests that pinned their texts.
- **`togi-machine`** decodes and encodes with serde derive: no case folding, duplicate-key rule, nesting limit, U+FFFD replacement or Go escaping. Host text is a `String`, vocabulary enums keep an `Unknown` variant only where the spec needs unknown values, and the seams return `Result`. `TargetOffset` and `ObservedOffset`, the std-only cancellation token and the workload table are unchanged in behavior.
- **`togi-machine` API, second pass.**
  - A seam that keeps progress across a failure returns `Result<T, Partial<T>>` (`Running::wait`, `Host::ranking`); `Kernel::read_mces` returns `Result<KernelRead, Partial<Vec<Mce>>>`. The `Waited` and `Ranking` structs and `KernelRead.error` are gone.
  - `BootId` and `KernelCursor` replace string ids; reading a whole boot is `after: None`.
  - Optional facts are `Option`: `ResetReason.kind` (`None` is no reason line, `Some(Unknown)` an unrecognized one), `TrialResult.inconclusive` and `TrialResult.failure` (signal and core together).
  - Scalars are narrower: pids and stops/conts `u32`, `CpuId(u16)`, `CcdId(u8)`, MCE bank `u16`, `boost_limit_mhz` `u32`. `BiosContext::first_difference` replaces `compare_context`; `PerCore` has `iter` and `FromIterator`, and `CoreSet` is a `u16` bitmask of cores that serializes as a sorted array, and `CancellationToken::on_cancel` runs a callback once on cancellation and returns a deregistering `OnCancel` guard.
  - `LoadSchedule` (R3 random, R4 duty) landed with `Started.schedule`; random periods come from `rand`'s `StdRng`, pinned to one `rand` version, not Go's PCG stream.
  - `Stopped` and `SmuValidated` are proofs only a seam implementation mints (clippy-gated), required by `Running::stop`, `Trials::start` and `Smu::emergency_zero`.
- **`togi-requests`** lost its Go leftovers: `f64::total_cmp`, `f64::max` and `f64::midpoint` replace the ported Go ordering, maximum and midpoint, and the NaN and signed-zero tests went with them: `summarize` skips a sample with a non-finite voltage lane, and `groups`, `top` and `counts` take finite inputs (checked with `debug_assert!`). Medians sort in place. `summarize` takes a `CoreSet`, so a core cannot repeat (Go counted a repeated core twice per sample), and the `counts` rounding tolerance is a named constant.
- **Size.** As first pushed, the change removed 1,011,907 lines under `crates/` and added 1,497 (65 files), mostly the deleted vector files; across the whole tree it removed 1,018,060 and added 1,599 (105 files). The review fixes added tests on top.
- **Review findings.** Sixteen reviewers found three P1 defects in the new `CancellationToken::on_cancel`: dropping a guard destroyed its callback while holding the slot lock, which deadlocked when a captured value cancelled the token on drop; a guard drop could return while a concurrent cancel had already claimed the callback but not yet run it; and a panicking callback stopped `cancel` before the remaining callbacks and child tokens. All three were fixed: the callback is destroyed with no lock held, the drop waits for a claimed callback unless it runs inside that callback, and `cancel` finishes every callback and child before re-raising the first panic. P2 fixes: `Partial` reports its named `Error` as its source, the R4 duty is a `DutyPct` checked to 0–100 instead of clamped at run time, the partial-ranking test came back, and native gzip tests cover a member larger than the window, a truncated body, a corrupt body, trailer mismatches, trailing data and an empty stale temporary directory. A fourth P1, that the compressed file's close error goes unchecked, was rejected: the file is synced before the close, so a close error reports no lost write.
- **Not measured.** Compile and test times against Go, and agent cost.
