# Rust migration log

The log of the move from Go to Rust ([#634](https://github.com/shgew/togi/issues/634), [ADR 0048](adr/0048-rust.md)). The rules are in [`porting.md`](porting.md), and the contract is [ADR 0058](adr/0058-native-rust-rewrite.md). Every stage appends an entry for what its pull requests measured and found: dates, lines removed and added, compile and test times next to Go's, regressions, review findings, and agent cost where known. Stage 12 ([#647](https://github.com/shgew/togi/issues/647)) turns this file into a retrospective.

Append entries below the last one, newest last. State what was measured and how, and name what was not measured.

## Stage 0: the probe (2026-10-10)

**Question.** Is Rust worth porting togi for, and how much of the cost in a heavy simulated session is the language rather than the code's design?

**Setup.** Branch [`rust-probe`](https://github.com/shgew/togi/tree/rust-probe/prototype/rustprobe), commit 4b20b151, `prototype/rustprobe/`. It is throwaway and never merges. It ports the hottest allocating path of a simulated session: simulated trial conditions → `session.sampleEvidence` → `requests.Summarize`. The input is all 30,177 trials listed in `trials.tsv`, drawn from the `flat-hazard` session at seed 102 (217,192 journal events). Five variants produce byte-identical output; hyperfine ran each for 10 runs.

- `go-verbatim`: the Go code as on `main` at the time, a fresh map per sample.
- `go-tuned`: the same logic without per-sample allocation.
- `rust-verbatim-std`: a straight port of `go-verbatim` with std `HashMap`.
- `rust-verbatim-fx`: the same port with the Fx hasher.
- `rust-tuned`: mirrors `go-tuned` line for line.

**Code size.** The probe adds 609 lines in its Go implementation and 653 in its Rust implementation, containing both verbatim and tuned variants; it removes no production code. This is an experiment's size, not a production port's reduction.

**Session profile on `main`** (the profile that picked the path): background garbage collection took about 30% of user CPU, 2.24 s against 1.57 s with `GOGC=off`, and the process peaked at 405 MB.

**Results** (`single.md`; peak memory is the largest `memory_usage_byte` of the 10 runs):

| Variant | Mean wall [s] | Min [s] | Max [s] | Relative | Peak memory [MB] |
|:---|---:|---:|---:|---:|---:|
| `go-verbatim` | 4.209 ± 0.219 | 3.991 | 4.501 | 13.80 ± 0.77 | 14.8 |
| `rust-verbatim-std` | 2.495 ± 0.038 | 2.463 | 2.598 | 8.18 ± 0.21 | 5.7 |
| `rust-verbatim-fx` | 1.258 ± 0.100 | 1.184 | 1.411 | 4.12 ± 0.34 | 5.3 |
| `go-tuned` | 0.469 ± 0.014 | 0.457 | 0.503 | 1.54 ± 0.06 | 12.0 |
| `rust-tuned` | 0.305 ± 0.006 | 0.300 | 0.320 | 1.00 | 5.4 |

**Findings.**

- Design dominates. Removing the per-sample allocation took Go from 4.21 s to 0.47 s, 9×. [#629](https://github.com/shgew/togi/issues/629) applied that fix to the Go code (PR [#648](https://github.com/shgew/togi/pull/648)): on the same session, user CPU fell from 2.48 s to 1.87 s and total allocation from 2.49 GB to 1.25 GB, with every journal and `samples.jsonl` byte-identical.
- The language adds about 1.5× (`go-tuned` 0.469 s against `rust-tuned` 0.305 s) and about half the peak memory on this path.
- A straight Rust port is not fast by itself: with std `HashMap` it took 2.50 s, 8× the Rust-native version. The decision to port Rust-native rather than verbatim (ADR 0048) rests on this.
- Rust is not free of the same design flaw: swapping the hasher alone halved the verbatim port's time, which is why dense per-core arrays replace `map[int]…` in the port guide.

**Limits.** One path, one session and one build of each language. It measures wall time and peak memory of that kernel, not compile time, test time, the effect on agent-driven development, or a whole-session Rust comparison. Comparison failures, regressions, independent review findings and agent cost were not recorded for the probe. The pilot (stage 2, [#637](https://github.com/shgew/togi/issues/637)) records compile and test times against Go's.

**Decisions.** The owner decided on 2026-10-10 to migrate ([#634](https://github.com/shgew/togi/issues/634)), and that agents merge migration pull requests once CI and the `review` check pass and every thread is resolved, except the cutover and changes to the protected comparison assets. The same day, the Go structure-only issues the port replaces were closed ([#104](https://github.com/shgew/togi/issues/104), [#124](https://github.com/shgew/togi/issues/124), [#321](https://github.com/shgew/togi/issues/321), [#322](https://github.com/shgew/togi/issues/322), [#323](https://github.com/shgew/togi/issues/323), [#550](https://github.com/shgew/togi/issues/550), [#552](https://github.com/shgew/togi/issues/552), [#562](https://github.com/shgew/togi/issues/562), [#565](https://github.com/shgew/togi/issues/565) to [#568](https://github.com/shgew/togi/issues/568), [#573](https://github.com/shgew/togi/issues/573), [#575](https://github.com/shgew/togi/issues/575), [#577](https://github.com/shgew/togi/issues/577)) and [#541](https://github.com/shgew/togi/issues/541)'s type cut was superseded; their designs are in the porting guide.

## Stage 2: the start and the reversal (2026-10-11)

The owner started stage 2 ([#637](https://github.com/shgew/togi/issues/637)) on 2026-10-11 under [ADR 0057](adr/0057-running-the-rust-migration-unattended.md). Its crates then matched Go: `togi-version` ([#696](https://github.com/shgew/togi/issues/696)), `togi-trialfiles` ([#695](https://github.com/shgew/togi/issues/695)), `togi-machine` ([#703](https://github.com/shgew/togi/issues/703)) and `togi-requests` ([#704](https://github.com/shgew/togi/issues/704)) landed, and a Go-compatibility crate with its vector generator, a comparison harness and a guard were built around them.

The same day the owner reversed the contract ([#737](https://github.com/shgew/togi/issues/737), [ADR 0058](adr/0058-native-rust-rewrite.md)): the port is native, journals and state are not compatible with Go's, and a Go bug found while porting is fixed in the port. The Go-compatibility crate, the vector generator, the comparison harness and the guard were deleted, and nothing they measured is carried forward. `togi-trialfiles` and `togi-machine` were rewritten on flate2, std errors and serde defaults. The four entries below record the surviving crates as they first landed; the native rewrite entry after them records what changed.

## Stage 2: the root package (2026-10-11)

The `togi-version` crate ports `version.go` ([#696](https://github.com/shgew/togi/issues/696)): 33 lines of library and 32 of tests against Go's 48 and 84, with the Go package unchanged. `version()` is the trimmed `version.txt`, embedded at compile time; `rev()` is the `TOGI_REV` the build sets at compile time, which plays the part of Go's `-X github.com/shgew/togi.rev`; `string()` joins them with `+`.

- **Departure from Go, the owner's call.** A local cargo build reports `dev`. Go reads the commit and dirty flag from the build's VCS settings, which cargo does not record, so that branch has no port; `bench` and `forecast` read the commit from git at run time instead (#637, Version stamps).
- **Not yet stamped.** The flake builds no Rust package until the binary lands (stage 7), so nothing sets `TOGI_REV` yet; that package's derivation sets it from the flake revision as `packages.default` does for Go.
- **Not measured yet.** Compile and test times wait for the stage's measurements pull request.

## Stage 2: `internal/trialfiles` (2026-10-11)

The `togi-trialfiles` crate ports `internal/trialfiles` ([#695](https://github.com/shgew/togi/issues/695)): 1,923 lines of library and 1,555 of tests against Go's 140 and 295, with the Go package unchanged. Most of the library is not the port itself: `goerr.rs` holds Go's errno tables, `goos.rs` Go's `os.Remove`, `Rename`, `ReadDir` and checked close, and `gzip.rs` with its `flate` module Go's `gzip.Reader` and `compress/flate` decompressor (including `flate: corrupt input before offset N` and the bytes delivered before an error), so that the errors `Compress` writes verbatim into the journal (`session.warning.error`) and `Open`'s header errors read as Go's do. It removes the placeholder crate and the `--no-tests=pass` flags the empty workspace needed.

- **One departure from Go: the compressed bytes.** `Compress` writes the same gzip container, with Go's default header (`1f 8b 08 00 00 00 00 00 00 ff`), but flate2's DEFLATE encoder chooses different blocks than Go's `compress/gzip`, so the same input compresses to different bytes. No spec, comparison (`tools/bench/same.go` skips trial directories), golden file or consumer depends on those bytes; the spec freezes the gzip container and the decompressed content.
- **Dependencies this crate introduces.** `flate2` with its pure-Rust `miniz_oxide` backend, because std has no DEFLATE: it supplies the compressor and the CRC-32. Its decoders are not used, because they differ from Go's observably (a stream decoder can drop already decoded bytes when it meets corrupt data, where Go hands them over before the error), so the decoder is the port above. `nix` as a safe wrapper where rustix has no safe API: the checked close (rustix's `close` is `unsafe`, std's `File` drops the close error, and `unsafe_code` is denied here) and `mkfifo` for the tests on Apple. `rustix` for `unlink`, `rmdir`, `rename` and the open flags; `thiserror` for the error enums.
- **Go's error text.** `goerr.rs` renders each failure like the `*os.PathError` or `*os.LinkError` Go returns (`op path: errno text`, the ops Go uses at each call), with the errno strings of Go's tables for Linux (amd64 and arm64, which differ only by errno 133) and Apple, `errno N` for an unknown one, and paths as `filepath.Join` cleans them, and `invalid argument` for a path with an embedded NUL. The errors keep Go's raw path bytes, because a workload chooses its directory names and Go's JSON encoder writes each invalid byte as the literal U+FFFD character, the same bytes a real U+FFFD becomes: `go_text()` on `Error` and `Errors` returns Go's exact `err.Error()` bytes for the journal encoder to serialize with Go's JSON rules, while `Display` shows each invalid byte as the character U+FFFD. It moves to `togi-gocompat` when a second crate needs it. `Remove` also removes an empty directory, and `Rename` refuses to replace a directory (EEXIST), as Go's `os` does; `ReadDir` skips an entry that vanished before its type lookup.
- **Not measured yet.** Compile and test times wait for the stage's measurements pull request.

## Stage 2: `internal/machine` (2026-10-11)

The `togi-machine` crate ports the shared vocabulary, dense per-core readings, workload catalogue, diagnostic sample reader and synchronous machine seams ([#703](https://github.com/shgew/togi/issues/703)): 1,819 lines of library and 1,398 of tests, against Go’s 615 and 346 excluding the schedule. No Go code is removed or changed. The later journal, requests, simulator, session, SMU and trial crates consume these types; this crate does not yet drive a simulated session.

- **Offset types.** `TargetOffset::new` validates [-50, 0]; `TargetOffset::clamped` preserves the explicit Go clamps. `ObservedOffset` carries any signed 64-bit readback, baseline or decoded journal offset, including +10 and values below -50, and encodes as a JSON integer. The nine production clamp expressions are the driver’s per-core and all-core setters (`internal/smu/driver.go:100,114`), the session’s starting candidate and restoration (`internal/session/session.go:1060,1455`), reset’s starting candidate (`internal/tuner/reset.go:46`) and the four generated simulator limit expressions (`internal/sim/sim.go:483,487,489,490`). The tuner also has one-sided bounds in `search.go:40,58,144` and `constraints.go:91`; those remain distinct from constructor validation.
- **Shape choices not fixed by the plan.** Core IDs have checked constructors; CCD and logical CPU IDs are separate signed newtypes. Unknown MCE attribution is `None`, corresponding to Go’s core -1, rather than an invented supported core. Vocabulary enums keep an `Unknown` variant so permissive journal values survive; it wraps a type whose only constructor is the normalizing `From`, so a named or empty string has one value, as in Go, and explicit empty variants distinguish no signal or reset reason from the named unknown reason. Workloads live in static arrays and catalogue reads allocate nothing. `NanoDuration(i64)` preserves signed Go durations; `jiff::Timestamp` carries wall time. Cancellation is std-only (`Arc`, `AtomicBool`, `Mutex`, `Condvar`): clones share cancellation, child tokens inherit it without cancelling their parent, and waits need neither a runtime nor polling. Stage 5 bridges this token inside its async adapters; no Tokio dependency reaches machine. `HostText` keeps raw host/kernel bytes, replacing each invalid UTF-8 byte individually when comparing BIOS context and and writing each invalid byte as the literal U+FFFD character when encoding JSON, as Go’s encoder does (there is no escaped form). One string writer serves `HostText` and the vocabulary types.
- **Ownership.** Machine owns its seam adapters. Reporter callbacks borrow a non-`Send` trait object on the waiting thread; implementations must join before returning from wait, and stop must join and retain its first result. The SMU seam keeps separate read, per-core write and all-core write methods; only reads return raw observed offsets. Both write methods now have active Clippy tripwires. A separate throwaway caller failed on both forbidden methods as intended.
- **Diagnostic samples.** The reader uses `togi-trialfiles` for plain-first and gzip behavior, yields complete valid lines only, ignores undecodable lines, discards torn tails and closes on early iterator drop. Decoding retains Go’s null handling, duplicate-field updates, case folding, unsupported-core rejection, short/long fixed-array handling and invalid-string replacement. `json_text` is the one entry point that turns bytes Go wrote into text serde decodes as Go does (invalid bytes and unpaired surrogates become U+FFFD, nesting beyond 10000 levels is an error); `ReadSamples` and the journal use it, and one struct-decoding helper serves `TrialConditions`, `PmTable`, `CoreInfo`, `BiosContext` and `PstoreRecord`. PM-table numbers parse directly as `f32`, avoiding an `f64` intermediate; a midpoint-adjacent input pins the double-rounding hazard.
- **Precisely deferred to stage 4.** As #637 and #639 specify, `loadsteps.go`, `TestLoadSchedule` and `Started.Schedule` land together with PCG. `PmTable` and `TrialConditions` intentionally have no general-purpose serialization implementation: their Go writers live in `internal/sim/samples.go` and `internal/trial/samples.go`. Before the simulator writes samples, #639’s float32 acceptance requires Go-generated bit-width-32 vectors and `togi-gocompat` formatting whose shortest digits and exponent thresholds are evaluated at that width; then the sample encoder must use it for all six PM-table arrays and `json_f64` for package power, preserve field order and Go’s omission rules, and never fall back to Serde’s float formatter.
- **Tests and findings.** All eleven in-scope Go tests have named Rust equivalents; the PR records their map and the excluded schedule test. Additional properties cover all signed offset inputs, sparse per-core JSON round trips and unknown vocabulary strings; real-thread tests cover shared and child cancellation and waking waiters without sleeps. Tests caught an external `io::Error` wrapper hiding its joined inner sentinels from a plain source-chain walk; classification now inspects the retained inner error, and the regression passes. The gate rejected a path-only workspace dependency as a wildcard; the dependency now also declares the internal crate’s version. The PR attaches the changed-line coverage output, including #733’s false “not built” classification of the module-only `lib.rs`. Debug and release tests, host and aarch64 macOS Clippy, and the target-constructor compile-fail doctest passed.
- **Review findings fixed.** Invalid host bytes were written as the escape `\ufffd` where Go writes the literal U+FFFD; vocabulary strings skipped Go’s escaping of U+2028/U+2029 and `<>&`; `Unknown` could hold a named or empty string; invalid UTF-8, unpaired surrogate escapes and the 10000-level nesting limit were not Go’s at the decoding boundary; duplicate PM-table arrays erased readings under `null` elements; `CoreInfo`, `BiosContext`, the ID types and `PstoreRecord` decoded with derived Serde instead of Go’s struct rules (folding, duplicates, `null`, and a later array reusing an earlier one’s elements); and the property tests used a random seed. A second review found that routing vocabulary serialization through `RawValue` made every vocabulary type fail as a JSON map key, which Go’s simulator maps use; it now writes a plain string whenever serde’s bytes equal Go’s and errors otherwise. Each fix has Go 1.27.1-generated vectors.
- **Not measured.** Isolated compile/test times against Go, whole-session comparison cost, independent review findings and agent cost are not measured here; the stage’s measurements and the first consuming crates provide those records. No behavior regression or change to a protected Go/comparison asset is intended.

## Stage 2: `internal/requests` (#704, 2026-10-11)

The `togi-requests` crate ports `internal/requests` ([#704](https://github.com/shgew/togi/issues/704)) with the Go package unchanged. `summarize`, `groups`, `counts` and `top` keep Go's statement order and arithmetic, and the package reads and writes no files, so no path, mode or `os` error text is involved.

- **Types.** Loaded cores are `CoreId`, CCDs are `CcdId`, and `Telemetry` holds `PerCore<f64>`, `Vec<CoreId>` and `BTreeMap<CcdId, i64>`. Go's nil and empty collections are one value here: `summarize` returns `None` where Go returned `false` with the zero `Telemetry`, and a `Some` always holds at least one request, one top requester and an optional, possibly empty, CCD map. Go's out-of-range core check cannot arise: a core outside 0–15 never reaches the crate, because its caller cannot build a `CoreId` from it.
- **Early exit.** Go's `Summarize` returns as soon as a core is out of range or the samples run out, leaving its caller's iterator to drain; the Rust function takes an `IntoIterator` and drops it on return, so a caller that must see every sample passes `&mut iterator` or wraps it.
- **Duplicate cores.** A core listed twice is appended twice per sample, as in Go, so it counts twice in its CCD's clock median.
- **Tests.** The six Go tests, with the four `TestGroups` cases as one table, map to `summarize_uses_samples_after_warmup`, `summarize_needs_min_samples_after_warmup`, `summarize_needs_min_clock_samples_per_ccd`, `summarize_skips_samples_without_lanes`, `groups_orders_by_request` and `counts_raises_a_request_by_whole_counts`. Added: no cores, a repeated core, NaN and signed zero in `groups` and `top`, the empty `top`, and the boundary of the comparator (`compare_orders_nan_first_and_signed_zeros_equal`).

## Stage 2: native rewrite of `togi-trialfiles` and `togi-machine`, `togi-requests` adapted (#737, 2026-10-11)

- **`togi-trialfiles`** reads and writes gzip with flate2 (`MultiGzDecoder` and `GzEncoder`) and reports std `io::Error`s that name the path. It keeps what the crate is for: compression writes the `.gz` whole under a temporary name, syncs it, renames it into place and only then removes the plain file, so a reader finds one complete form at every moment; a symlinked log or instance directory is never followed; `open` prefers the plain file and falls back to the compressed one. Its ported gzip and DEFLATE readers, Go errno tables and Go `os` behaviors are gone, with the tests that pinned their texts.
- **`togi-machine`** decodes and encodes with serde derive: no case folding, duplicate-key rule, nesting limit, U+FFFD replacement or Go escaping. Host text is a `String`, vocabulary enums keep an `Unknown` variant only where the spec needs unknown values, and the seams return `Result`. `TargetOffset` and `ObservedOffset`, the std-only cancellation token and the workload table are unchanged in behavior.
- **`togi-machine` API, second pass.**
  - A seam that keeps progress across a failure returns `Result<T, Partial<T>>` (`Running::wait`, `Host::ranking`); `Kernel::read_mces` returns `Result<KernelRead, Partial<Vec<Mce>>>`. The `Waited` and `Ranking` structs and `KernelRead.error` are gone.
  - `BootId` and `KernelCursor` replace string ids; reading a whole boot is `after: None`.
  - Optional facts are `Option`: `ResetReason.kind` (`None` is no reason line, `Some(Unknown)` an unrecognized one), `TrialResult.inconclusive` and `TrialResult.failure` (signal and core together).
  - Scalars are narrower: pids and stops/conts `u32`, `CpuId(u16)`, `CcdId(u8)`, MCE bank `u16`, `boost_limit_mhz` `u32`. `BiosContext::first_difference` replaces `compare_context`; `PerCore` has `iter` and `FromIterator`, and `CoreSet` is a `u16` bitmask of cores that serializes as a sorted array, and `CancellationToken::on_cancel` runs a callback once on cancellation and returns a deregistering `OnCancel` guard.
  - `LoadSchedule` (R3 random, R4 duty) landed with `Started.schedule`; random periods come from `rand`'s `StdRng`, pinned to one `rand` version, not Go's PCG stream.
  - `Stopped` and `SmuValidated` are proofs only a seam implementation mints (clippy-gated), required by `Running::stop`, `Trials::start` and `Smu::emergency_zero`.
- **`togi-requests`** lost its Go leftovers: `f64::total_cmp`, `f64::max` and `f64::midpoint` replace the ported Go ordering, maximum and midpoint, and the NaN and signed-zero tests went with them: `summarize` skips a sample with a non-finite voltage lane, and `groups`, `top` and `counts` take finite inputs (checked with `debug_assert!`). Medians sort in place. `summarize` takes a `CoreSet`, so a core cannot repeat (Go counted a repeated core twice per sample), and the `counts` rounding tolerance is a named constant.
- **Size.** As first pushed, the change removed 1,011,907 lines under `crates/` and added 1,497 (65 files), mostly the deleted vector files; across the whole tree it removed 1,018,060 and added 1,599 (105 files). The review fixes added tests on top.
- **Review findings.** Sixteen reviewers found three P1 defects in the new `CancellationToken::on_cancel`: dropping a guard destroyed its callback while holding the slot lock, which deadlocked when a captured value cancelled the token on drop; a guard drop could return while a concurrent cancel had already claimed the callback but not yet run it; and a panicking callback stopped `cancel` before the remaining callbacks and child tokens. All three were fixed: the callback is destroyed with no lock held, the drop waits for a claimed callback unless it runs inside that callback, and `cancel` finishes every callback and child before re-raising the first panic. P2 fixes: `Partial` reports its named `Error` as its source, the R4 duty is a `DutyPct` checked to 0–100 instead of clamped at run time, the partial-ranking test came back, and native gzip tests cover a member larger than the window, a truncated body, a corrupt body, trailer mismatches, trailing data and an empty stale temporary directory. A fourth P1, that the compressed file's close error goes unchecked, was rejected: the file is synced before the close, so a close error reports no lost write.
- **Not measured.** Compile and test times against Go, and agent cost.

## Stage 4: `internal/tuningboot` (#739, 2026-10-11)

The `togi-tuningboot` crate ports `internal/tuningboot` ([#739](https://github.com/shgew/togi/issues/739)): 444 lines of library and 617 of tests, against Go's 232 and 240. No Go code is removed or changed. The real `grub-editenv` implementation lands with the hardware crate and the retry-marker file with the binary.

- **Seams.** `Environment` and `Bootloader` return `io::Result`, with `None` for an unset variable where Go returned `""`; an empty stored value still reads as unset. The free functions take `&mut (impl Environment + ?Sized)`, so the session's `Box<dyn Bootloader>` works. `restart_limit` returns `RestartLimit::Retry(count)` or `Exhausted`, never a count with a boolean beside an error.
- **Invalid records are unrepresentable.** `ReasonId`, `RestartCount` and `ReasonText` validate on construction and on Serde decoding, so `write_reason` has no invalid-metadata error and Go's `validateReason` runs once, in the constructors. Reason text must also not start or end with a space; Go accepted such a record from the environment, and `ReasonText::sanitize` never produced one.
- **Strict decoding.** `LeaveReason` decodes only from a JSON object, through a hand-written `Deserialize`, with positional arrays, unknown fields, missing fields, trailing data and duplicate fields rejected; Go accepted a duplicate field and kept the last value. Records over 300 bytes or outside printable ASCII are refused before parsing.
- **Encoding.** The 300-byte budget counts only the two bytes of `"` and `\`: Go also reserved six bytes per `<`, `>` and `&` for its HTML escaping, which `serde_json` does not do, so those reasons now keep more text.
- **Tests.** The eight Go tests map to `two_retries_then_exhaustion_clears_saved_entry_and_stays_at_three`, `invalid_counts_grant_no_retry_and_write_nothing`, `a_failure_at_each_step_grants_no_retry_and_leaves_only_what_happened`, `reason_round_trips_through_the_environment_and_cleans_up_independently`, `sanitize_replaces_cuts_and_trims` with `encoded_records_fit_and_round_trip_for_hostile_reasons`, `decoding_rejects_invalid_records`, `constructors_refuse_invalid_metadata` and `failed_operations_preserve_state`. Added: the count table, a retry never clearing the saved entry, a trait object, error display, `RestartCount::next` saturating, two fixed-seed properties that any text encodes to at most 300 printable bytes and decodes back, array records in `decoding_rejects_invalid_records`, `a_random_failure_grants_no_retry_and_touches_nothing` and `quotes_and_backslashes_in_a_reason_are_escaped_and_decode_back`.
- **Review findings fixed.** Decoding is now object-only, so a positional array such as `["test",0,"retry"]` is rejected; `encode` writes the record directly, so production code has no `expect`; the randomness failure in `restart_limit` is tested through a private ID-source seam; and the workspace `getrandom` pin moved to 0.4, which removes the duplicate 0.3 copy and its subtree from `Cargo.lock`.
- **Not measured.** Isolated compile and test times against Go and agent cost were not measured. Byte comparison with Go's records does not apply under the native contract.

## Stage 4: `internal/sim` (#740, 2026-10-11)

The `togi-sim` crate ports `internal/sim` ([#740](https://github.com/shgew/togi/issues/740)): 4,492 lines of library and 6,573 of tests, against Go's 2,808 and 4,057. No Go code is removed or changed. It depends on `togi-machine`, `togi-trialfiles` and `rand`, not on the journal: Go's replay-fact types are the crate's own `ReplayFact`, and Go's `Resume` becomes the `History` the caller builds from the journal.

- **One hazard model.** `Model` (an `Arc`, immutable) is both the machine and Go's `Predictor`. `visit_sources` lists every source of failure in a fixed order, and scoring (`hazard`, `failure_probability`, `r7_failure_share`) and the runtime's competing draws walk it; `Onset::failure_time` inverts `Onset::exposure`, which a property test pins.
- **Runtime.** `Simulator` shares one `Rc<RefCell<Runtime>>` among the clock, SMU, host, trials and kernel adapters, and never holds a borrow across a reporter or hook call. A trial is a state enum (started, waited), consumed by `stop`, so Go's repeated `Wait` and `Stop`-then-`Wait` cannot happen.
- **Validation** is strict and field-named (see [simulating](simulating.md#the-rust-simulator-togi-sim)). The Go holes found: unchecked rates, growth, probabilities and onset, infinite weights, a joint rate of `0` standing for "the model's", encoding that could write a machine that does not load, and reset weights that fell back silently.
- **Randomness** is a splitmix64 fold into `StdRng`, one typed `Domain` per stream. Go keyed streams by formatted strings and legacy condition names.
- **Tests.** Every Go test of the package maps to a Rust test or a stated reason (mapping in the pull request). Draw-exact Go tests became properties: the failure share of a few thousand seeded trials within five binomial deviations of `failure_probability`, same seed and history giving the same transcript, retries reproducing the class outcome, unloaded draws keyed by the loaded set, telemetry changing no failure.
- **Not measured.** Compile and test times against Go, and agent cost.

## Stage 4: `tools/trialfacts` (#744, 2026-10-11)

The `togi-tool-trialfacts` crate ports `tools/trialfacts` ([#744](https://github.com/shgew/togi/issues/744)): 827 lines of library and 1,405 of tests, against Go's 176 and 438. No Go code is removed or changed. It also adds `StateDir::recordings` and `Recording::into_events` to `togi-journal`: every archived journal oldest first, then the live one, which Go's `facts.ReadDir` did over paths.

- **One record, one format.** `TrialFact` serializes to the field names the committed `tools/bench/facts/target.jsonl.gz` uses, so the Rust reader reads that Go-written asset unchanged and the suite's `--replay-facts` scenarios keep their oracle. Differences: a `build.evidence` field the Go extract did not have (absent reads as `None`); `record_only` and the `confirmation` phase survive only for reading the asset, since the Rust journal records neither; `phase` is omitted when the intent names no activity; and a failure outside any trial is `kind: "idle"` with no workload.

The bytes are the same for the same facts.
- **Extraction.** `extract(&StateDir)` folds each journal through `togi_facts::extract`, orders sessions by id and keeps each session's own decisive and idle facts (carried copies belong to the session they came from). A profile with a hole below its highest core, which the extract has no way to say, is refused rather than filled.
- **Key and replay.** `ProfileClassKey` is `Copy + Hash` (profile and class), with no JSON. `Extracts` owns its cache, keyed by the joined path of the machine file's `facts`, and shares each read as an `Arc`; `replay_facts` keeps decisive trials with a context and feeds `togi_sim::replay::Replay`. Replay needs the machine to declare its BIOS context, as the simulator's documentation says.
- **Config.** `togi_config::CheckingSchedule::is_full` and the tuner's full-cycle coverage share one table, `FULL_CYCLE`. `docs/spec/runtime.md` says `run --cycles N` and `run --first-result` refuse a schedule that is not full; the session and CLI implement the refusal.
- **Go bugs fixed.** `ProfileClassKey` marshalled JSON into a string and dropped the error; `Read` accepted any JSON value stream and `{}`; a zero-value `Extracts` panicked on its first store. Sample-file telemetry backfill and the older-vocabulary translation are not ported: the Rust journal records the request summary, and no Go journal is read.

## Stage 5: `internal/hostlock` (#747, 2026-10-11)

The `togi-hostlock` crate ports `internal/hostlock` ([#747](https://github.com/shgew/togi/issues/747)): 351 lines of library and 594 of tests, against Go's 148 and 400. No Go code is removed or changed. It builds on Linux and macOS only (`#![cfg(unix)]`), and the 20 tests run in 0.02 s under `cargo nextest` on Linux.

- **Policy.** `HostLock::acquire(path, Policy)` takes `Policy::Host` (root-owned lock, only root creates it) or `Policy::Private` (root or the caller). Go chose its policy by comparing the path string with `Path`; a differently spelled path silently got the weaker policy. The lock is a `HostLock` guard: dropping it closes the descriptor and releases the `flock`, nothing unlinks or replaces the inode.
- **Errors.** One `Error` variant per refusal an operator distinguishes: `Busy`, `NotProvisioned`, `UnsafeDirectory` and `UnsafeLock`, each with a problem enum, and `Io` naming the failed `Operation` and keeping the `io::Error`. Go returned its sentinel with the errno dropped.
- **Pure decisions.** The directory and lock ownership rules are functions of plain facts (`directory_problem`, `lock_verdict`), so the authorization matrix runs without root.
- **Changes from Go.** A symlink or directory at the lock path is `UnsafeLock`, not an open errno. A hard-linked lock is `MultipleLinks`. A permission failure while creating the lock reports the create failure instead of retrying read-only and reporting a missing file. `flock` comes from `File::try_lock`.
- **Tests.** The ten Go tests map one to one (`exclusive_until_dropped`, `legacy_locks_are_tightened_in_place`, `legacy_read_only_holder_stays_exclusive_through_migration`, `provisioned_group_lock_keeps_its_mode`, `concurrent_creators_yield_one_owner`, `unsafe_lock_objects_are_refused_untouched`, `writable_ancestor_needs_the_sticky_bit`, `directory_authorization_matrix`, `missing_parent_is_not_created`, `read_only_descriptor_to_a_secure_lock_is_refused_without_chmod`). Added: `real_process_excludes_until_it_exits` re-executes the test binary and sees `Busy` while the child holds the lock, `host_policy_leaves_provisioning_to_root`, `create_permission_failure_is_reported_as_create` (a non-writable directory gives the create failure and no lock file), `unopenable_lock_is_refused_untouched` (a `0o000` lock fails both opens with the open failure and keeps its inode, mode and contents), and the pure-function tests in `policy.rs`.
- **Not measured.** The macOS tests were not run here; the crate was linted for `aarch64-apple-darwin`. The host-policy test and the two permission tests need a non-root caller and skip as root, so they did not run as root here.
- **Review findings fixed.** The sticky-bit test depended on the umask: its containing directory came out group-writable under `umask 0002`. The test now sets that directory's mode, and the other tests start from a `0o700` temporary directory for the same reason; the crate's tests pass under `umask 0002`. The real-process test was outside nextest's `real-process` group and now carries the `real_process_` prefix. The create-failure fix and the open-refusal path had no test. The heading named stage 2; hostlock belongs to stage 5.

## Stage 2: native `togi-journal` (#705, 2026-10-11)

The journal starts its own schema (Rust schema 1); it reads no journal, `state.json` or archive the Go build wrote, and the cutover starts a fresh session. The `togi-journal` crate has about 5,950 lines of library and 6,440 of tests (unit tests, `tests/disk.rs` and the test helpers), against Go's 4,069 and 4,046 in `internal/journal`; no Go code is removed or changed. Its 281 tests run in 0.30 s under `cargo nextest` on Linux; `go test -count=1 ./internal/journal` reports 0.09 s. What changed against Go, as built:

- **Wire.** Every line is `seq`, `time`, `boot`, optional `mono_ms`, `cause` (omitted when empty), `kind`, `msg` and a `data` object. `Seq` is a non-zero integer, so a missing reference is `None`, never `0`. Payloads are one serde struct per kind with `deny_unknown_fields`; an unknown kind or field is a decode error that names the line and the kind. There are no opaque events, no registry beside the `Payload` enum, no case folding and no second parse.
- **Types.** Decided profiles are `PerCore<TargetOffset>` and baselines and readbacks are `ObservedOffset`, so an out-of-range target cannot be recorded. Core sets are `CoreSet`, workloads are `WorkloadId` (a catalog identity that serializes as the catalog id string, so an id outside the catalog does not decode), ordinals are `NonZeroU32`, kernel boundaries are `KernelCursor`, load steps are `LoadSchedule`, and every vocabulary is a closed enum with no empty or unknown value. Optional facts are `Option` and absent fields are omitted, where Go told absent from empty by `nil` against `[]`.
- **Go bugs fixed on the way.** `hold` is an explicit decision, not an equal-offset `backoff` whose reason starts `holds`. `trial.end.last_evidence` is persisted (Go kept it only in the message), and the checking chain's re-derivation is a field (Go kept it in an unstored message override). `trial.end.core` is optional, so a passing trial needs no dummy core. A carried copy records its original backend identity, so it never needs the original archive. `record_only`, `checking.step.partials` and the archive `path` are gone; paths follow from the session ID, which is checked (suffix arithmetic cannot overflow) and ordered numerically.
- **Strict nested decoding.** `deny_unknown_fields` covers the machine types inside payloads too (`CoreInfo`, `PstoreRecord`, `LoadSchedule`), so an unknown field at any nesting level is a decode error. The `samples.jsonl` types stay lenient: readers skip lines they cannot decode, and strictness there would drop samples a newer build wrote.
- **Messages.** `msg` is generated from the payload when the event is appended, stored, and never regenerated on read; units are in the text (`90 s`).
- **Writer.** One `write` and one fsync per event, and an event that would not decode again is refused before anything is written. A write or fsync error poisons the journal, and a reopen replays whatever survived. A torn tail is recorded as `journal.torn` through a temporary file, a rename and a directory sync next to the rename. A recorded archive is finished by what the journal records, so a torn tail after `session.archived` no longer hides it (Go missed that case). The lock is `std::fs::File::try_lock`.
- **SMU receipt.** `smu.intent` and `smu.write` cannot go through the generic append. A receipt is minted only after the durable intent, cannot be built, cloned or copied outside the crate, is bound to the journal that minted it, and is consumed by the write append. The simulator's unsynced journal writes the intent through to the file before minting, without an fsync; its receipts reach only a simulated SMU.
- **Storage seam.** Tests and simulations run in memory on `MemFs`, which injects faults and can dump to disk; `tools/sim --state-dir` uses unsynced, buffered disk. Both constructors and `MemFs::dump_to` are on clippy's `disallowed-methods` list, and the disk filesystem is private to the crate. The fault matrices prove recovery of each failure path, not survival of power loss.
- **Object-only decoding.** The envelope, every payload, every struct nested in one, `State` and the machine types inside payloads refuse serde's positional array form, through `togi_machine::serde_object`, which `togi-config` now shares.
- **Build verdicts.** `Build::verdict` compares schema, ruleset and evidence epoch separately for six operations; any newer dimension refuses a resume, and an older one archives. Go's missing-stamp defaults and unknown-kind policy are gone.
- **Config.** `config.loaded.config` is `togi_config::Config`, re-validated on decode; `State` folds the backend store paths from the latest `config.loaded`. Defect ids are non-zero.
- **Ownership.** The journal owns the schema, stored messages, build verdicts, the shared-facts `State` (a fallible fold: a structurally impossible journal is an error, never a panic), event filters, archives, markers, session IDs, the reset boundary, the boot-reason lookup and atomic publication of `state.json`. The session composes `state.json` from `State` and the tuner's projection; the journal never depends on the tuner.
- **Review findings fixed.** Storage: directory listings refuse a symlinked directory, the state directory gets its mode before the lock file is opened, `state.json` is published through a freshly created temporary file, the disk filesystem left the public API, and `MemFs` counts stacked faults and registers an open handle atomically. Archives: a surviving compat or carry marker is synced again before an archive resumes. Messages: a hunt end says it found a core only for a culprit, and a failure keeps its recorded trial when the condition is missing. Filters match a member probe's core and every `trial.start` instance. Envelope errors name the kind. Tests were added or tightened where the Go mapping was incomplete: the repair-fault matrix requires each faulted open to fail, a seq-1 non-start journal, boot identity across reopen, boot-reason negatives, a failing reader, recovery faults on an archived journal, the build matrix, `State` replacement rules and operator narratives. The specs now match the native build stamp and the carried backend rule.
- **Not measured.** Isolated compile times against Go (left to #708's measurements), throughput of append and replay, and agent cost. The fuzz target runs on `EventReader`; its findings are not recorded here.

## Stage 3: tuner state, search, constraints and evidence (#753, #754, 2026-10-11)

`togi-tuner` gains the tuner's folded `State` ([#614](https://github.com/shgew/togi/issues/614), ADR 0059) with the groups that cannot be tested apart: topology, search, the phases lifecycle, constraints, crash classification, reset (G1) and the evidence ledger, carried facts, intent-time requirements, retries and known-failure skips (G2). ## Stage 3: tuner R7, checking, rounds, later failures and hunts (#755, #756, #757, 2026-10-11)

`togi-tuner` gains the groups that sit on the state, search and evidence of the previous entry: R7 voltage-targeted backoff with its attribution, zero diagnostics and escalation (G3), checking cycles, chains, reruns, phase-2 rounds, blame, the confirmation cycle, ordinary backoff, held and paired later failures and the BIOS profile (G4), and hunts, located hunts and their commitments (G5). Against `origin/main` the branch adds about 9,500 lines of library files and 19,300 of test files in `crates/togi-tuner` (`git diff --numstat`), 388 `#[test]` functions among them; the crate's 621 tests run in about 3.6 s under `cargo nextest` on Linux. No Go code is removed or changed. Compile times and the comparison with `go test ./internal/tuner` are left to the closing stage (#759).

- **V\* index.** Voltage-target passes are grouped by class, backend package and profile. A group keeps only what R47 reads: for an unattributed failure the highest request on each CCD, for a named one the whole load's top request and that CCD's clock. Each entry holds one segment per covering-failure floor, with a count and the earliest witnesses, capped at `TrialCount::MAX` (1000). Whether a failure hides a pass is decided at query time against the evidence ledger, so a reset that drops a named failure gives its passes back. A test folds 100 and 10,000 passes and finds equal entries, segments and visits for the fold and for the query.
- **Explicit Hold.** A first later failure that is held is its own `hold` decision with equal `from_offset` and `to_offset`, not a backoff of no distance; the spec and ADR 0056 say so.
- **Fold-time work.** Rounds, blame, hunts, held failures and the BIOS profile are updated in the arm of the event that changes them. Hunt answers are frozen at fold, and a hunt keeps the `trials` it recorded at `hunt.start` however the configuration changes.
- **Go bugs fixed.** A failure's confirmation association was kept after its confirmation cycle ended (`phases.go:246-248`); it holds only while that cycle is open. A round's workload index no longer runs past the catalog (T22).
- **Fixed in pre-review.** A deepening yield retired another failure pending on the yielding core. A round base with the wrong topology was accepted at fold, and so was a round intent whose profile or target offset was not its check's. An MCE that named an unloaded core lost that core's request lane, so its backoff fell back to one count. ## Stage 5: `togi-command` (#760, 2026-10-11)

The `togi-command` crate runs external commands under a deadline ([#760](https://github.com/shgew/togi/issues/760)). It has no Go package: Go's `exec.CommandContext` killed only the direct child and `Output` waited on pipes a descendant still held (journalctl, systemctl, the systemd-run probe), `grub-editenv` had no deadline, and outputs were unbounded.

- **API.** `Invocation::new(program).arg(..).args(..).output_limit(bytes)` (1 MiB per stream by default; stdin is null, the environment is inherited, no shell). `run(&Invocation, Instant)` is async; `run_blocking(&Invocation, Duration)` builds its own current-thread runtime and returns `Error::InsideRuntime` when called inside one. A deadline that is not in the future returns `TimedOut` without starting the command, and a reaper thread that cannot be created returns `Io` with `Operation::StartReaper`, also before anything is started. A non-zero exit is data in `Output`; `Error` is `Spawn`, `TimedOut`, `OutputTooLarge`, `Io`, `InsideRuntime` or `Teardown`, each naming the program. `Teardown` keeps the error that ended the run beside the failure to kill the group or to reap the child.
- **Bound.** Each run first starts a reaper thread that blocks until it is handed a child, so once the command exists handing it off cannot fail; a run that settles normally drops the handle and the thread ends. The child is then spawned through `std` and owned from the moment it exists, so a failure while registering its pipes or exit watch tears it down like any other failure. It leads its own process group. The run ends when the child has exited and both pipes reached EOF, all within the deadline. At the deadline, on output over the limit, on an I/O or setup error, or when the future is dropped, the group gets SIGKILL and the pipes are closed. After a deadline, an overflow or an error the child is awaited for at most 1 s, so a child in uninterruptible sleep cannot hold the caller; a dropped future does not wait. A child still running then is handed to its reaper thread, which blocks in `waitpid` and outlives `run_blocking`'s runtime. A kill failure other than ESRCH, or a child not reaped within that second, returns `Teardown`; a dropped future has no caller to tell. On Linux the exit is watched through a pidfd and the child stays unreaped until the run is decided, so its group is killed even when it exited first and a descendant still holds the pipes, and the group id cannot have been reused. Elsewhere (macOS, development only) the exit is seen by reaping, so a child that exited before the deadline is not signalled: its descendants are not killed and only the pipes are dropped. A descendant that left the group (`setsid`) and holds the pipes cannot extend the wait, because the pipes are dropped. A timed-out run returns no output, so "not loaded" text from a timed-out systemctl cannot read as success.
- **Inventory.** `clippy.toml` `disallowed-methods` now lists `std` and `tokio` `Command::{spawn, output, status}` and `togi_command::{run, run_blocking}`. The runner's one spawn and every test helper that spawns carry `#[expect(clippy::disallowed_methods, reason = …)]`, including the real-process tests of `togi-hostlock` and `togi-journal` that re-execute their test binary, which landed before the inventory.
- **Tests.** Real processes, in tests named `real_process_*`: captured output and non-zero exit, a hung child, a group descendant holding the pipes, a descendant in its own session holding them (the test binary re-invoked as a helper that calls `setsid(2)`, since the Nix check sandbox has no `setsid` program), an exited child kept unreaped until a dropped future kills its group, output at the limit and one byte over on each stream, output over the limit with a group descendant alive before and gone after, a dropped future, `run_blocking` inside a runtime and outside one, and a missing program. Deadlines that have passed or are now return at once and start nothing. Unit tests inject a setup failure after the spawn, a failed or undelivered kill, a child outliving the 1 s grace (in place of uninterruptible sleep, which an unprivileged test cannot cause) and a reaper thread that cannot be created. The child is killed and reaped, or handed to the reaper thread, which collects it after `run_blocking`'s runtime is gone and after a dropped future the kill did not reach; the return stays within the grace; the error carries both failures; and a reaper thread that cannot start leaves no process started. A guard for a child the runner started is built only after a check that it is unreaped (a counter test shows a rejected guard signals nothing); a guard for a process that is not our child (a reparented descendant, a helper in its own session) holds a pidfd opened while it runs and signals through it, so an id init reaped and the kernel reused is never signalled, and off Linux no such guard signals by id at all.
- **Measurements.** Against the base `b4dd1cc`, the pull request changes 9 files, adding 1,535 lines and removing 9 (the removals rewrap the `clippy.toml` comment); no Go is removed. The crate's 28 tests take 6.2 s under nextest, the longest 3 s, waiting out a child that outlives the grace. Compile time is not measured. Review found 4 P1, 16 P2 and 1 P3 problems, all fixed here: in the runner, a child left unowned when setup failed after the spawn, discarded kill failures, a late child left to the orphan queue of `run_blocking`'s finished runtime, a reaper thread created only after the command existed, so a failure to create it, twice or once on a dropped future, left the child without an owner, and a command started after its deadline; in the tests, a `setsid` program the Nix sandbox lacks (it failed CI), missing limit-boundary and overflow-descendant cases, a racy zombie observation, helper and child processes left running when an assertion fails, kill guards armed on ids already reaped (one built eagerly and dropped when rejected, so it signalled the reaped id on every passing path) and on reparented descendants whose ids could be reused, real-process tests not named for their nextest group and an unchecked passed deadline; in this entry, a bound stated for every platform and missing measurements; a stale Go-test mapping in the pull request description; and sources committed as executable. ### Go `Forecast` cost, a performance reference for the tuner's forecast (G6)

The tuner's `Forecast(events)` replays the whole prefix from `New()` once for the base and once more for each premise branch, so one call costs (1 + branches) folds of the prefix and a session's calls cost quadratic time. This is the Go figure the Rust `forecast`, which copies the folded state per premise and never iterates events, is measured against; Go equality is not required.

- **Session.** `go run ./tools/bench --split all --keep DIR` over the suite at `8acbf3ca` kept 220 journals. The longest is `target-r7-request-gap`, holdout seed 110: 40,592 events and 2,266 trial intents. (The stage 0 session, `flat-hazard` seed 102, is 27,879 events on this commit.)
- **Command.** A throwaway program kept outside the repository read the journal with `journal.Read`, timed three full `tuner.New()` plus `journal.Replay` folds, then, for 800 prefix lengths drawn from a PCG(1, 2) stream and sorted, timed `Forecast(events[:p])` and the fold of that prefix alone. One process, one batch, one run per prefix; the process took 4.62 s of wall time, 5.83 s of user time and 69.1 MiB at peak. The load average was 4.67 when it started and 4.45 when it ended, above the load-3 rule, because the suite had just run on the same host.
- **Full fold:** 7.75, 7.86 and 7.05 ms, 191, 194 and 174 ns per event.
- **`Forecast` per prefix, 800 prefixes:** mean 3.86 ms (standard error 0.23 ms), median 1.92 ms, min 0.004 ms, max 39.5 ms; the mean over the last tenth of the session is 15.9 ms (88 prefixes). The fold of the same prefixes averaged 1.87 ms (max 8.2 ms); `Forecast` averaged 2.02 times its fold. Branches per call: median 0, maximum 5.
- **Whole-session cost.** Calling `Forecast` at every prefix would cost 40,592 × 3.86 ms ≈ 157 s of one core (standard error ≈ 9 s, a sampling estimate). The dashboard calls it once per refresh on the full journal; that call was not timed. The nearest sampled figures are the last tenth's mean, 15.9 ms over 88 prefixes, and the largest sampled call, 39.5 ms at 39,600 events.

### Decisions

- **Nightly `-Zthreads=0`: adopt, as an opt-in dev shell only.** It clears the threshold on all three metrics against stable (−44.7%, −34.9%, −29.5%). CI and the package stay on stable, and the shell is for a host where it is the only heavy job: the flag about doubles CPU use and with four jobs at once it ran slower than stable (5.527 s against 4.870 s median). The change needs `flake.nix`, so it is filed as [#791](https://github.com/shgew/togi/issues/791) under #637.
- **sccache: adopt for a clean build in a fresh worktree and for release builds, not for the edit loop.** Clean debug builds drop 41.1% and release builds 47.1% with a warm cache; the loop moves 3.9% and 1.5%, below the threshold, because sccache cannot cache incremental builds and the workspace crates. `CARGO_INCREMENTAL=0` by itself changes nothing in the loop. The first build on a cold cache costs 14.1% more. Filed as [#792](https://github.com/shgew/togi/issues/792).
- **Build cap: reject.** Four builds at once finish in 4.643 s (debug all-targets), 3.074 s (release) and 4.847 s (nextest), against 10.988, 7.857 and 11.842 s in sequence, and `MemAvailable` never fell below 13.5 GiB; the rejection rests on these two. The swap condition is not established either way: host-wide swap grew by at most 0.4 GiB during the cargo jobs, and host-wide counters cannot attribute it. Capping a single build's jobs also gains nothing (`-j8` to `-j32` are within noise).
- **Heavy-job cap: 2 concurrent (cargo build or nextest, VM tests, bench), unchanged from [ADR 0057](adr/0057-running-the-rust-migration-unattended.md).** The rule used here is the largest N whose per-job slowdown on the heaviest measured workload, `go test`, stays at or under 2 times, with no out-of-memory. `go test` slows 1.62 times at N=2, 2.29 times at N=3 and 2.93 times at N=4; the gate's 1.20, 1.40 and 1.69 and the cargo jobs' 1.16, 1.35 and 1.57 would allow 4, but a host runs a mix, and every mix with a Go test has to hold the 2. VM tests and bench were not measured.

### Limits

- The workspace is tiny: 6 crates, a clean build of under 3 s, and incremental builds of 0.07 to 0.7 s. Ratios here do not carry to the full port; the speed-ups especially will be measured again when the workspace is several times larger, and `-Zthreads=0` may gain more or less.
- Not like for like against Go: the Go module is about 20 times larger in lines (52,000 library and 75,000 test lines on an older base, against 6,061 of Rust), in 42 packages against 6 crates.
- One host, with `/tmp` on tmpfs, so disk speed is not in any figure. Other agents shared the host, so no run is isolated: starts at load 2.2 to 3.0, and the end-of-batch loads, which the batch itself raised (up to 95 after four concurrent `go test` jobs), are in the raw data, not shown. #637 asks for isolated loops with no sibling load; these runs do not meet that, and the re-run with no sibling load is [#796](https://github.com/shgew/togi/issues/796).
- hyperfine ran commands through a shell, and the prepare step was a shell script. The nightly toolchain was a single dated snapshot (2026-10-10), and sccache a single version.
- Run counts are 5 or 10, so every standard deviation is a small-sample estimate. The gate's fifth four-job repetition was cut off.
- Not measured: bench concurrency, VM tests, `just gate` in sequence, any build on macOS, any run on a GitHub runner, and agent cost. The `Forecast` probe is one process on one session at a load above 3, and its whole-session figure is a sampling estimate, not a run of the call at every prefix.

## Stage 5: `togi-trial` (#765, 2026-10-11)

The `togi-trial` crate ports `internal/trial` ([#765](https://github.com/shgew/togi/issues/765), pull request [#786](https://github.com/shgew/togi/pull/786)): `Runner` implements `togi_machine::Trials` and `Trial` implements `Running`. Every instance runs in a confined systemd scope under one supervisor task on a dedicated runtime thread, and only a teardown that ends with every scope seen empty mints `Stopped`.

- **Teardown.** A typestate (`Running → Reaped → ReadersDone → Verified → Ended`) shares one absolute 15 s budget across all instances: SIGTERM grace, one slot of scope kills, group SIGKILL and reap, a bounded drain, a `/proc` scan that every scope is empty, then a final re-read of the watched files whose writers are confirmed stopped. The launcher is owned by a pidfd as an unreaped zombie, so its group cannot be signalled after PID reuse.
- **Bounds.** The synchronous runtime requests `start`, `wait`, `stop`, `sweep` and `probe` each have a formula in `timing.rs`; `ended` compresses storage synchronously without a timeout, and `samples` opens storage synchronously and returns an iterator that reads the file lazily, so neither has that deadline guarantee. The start bound is prepare 10 s + 30 s per instance + 15 s teardown + 5 s margin. File preparation runs on a dedicated single-flight thread, and watched-file reads and `/proc` scans on the blocking pool, each under an absolute deadline that for the pool counts queue time; a stuck one is abandoned and never replaced while stuck. The samples and log writers run on their own std threads, and `join::report` waits for each on a oneshot with `timeout_at`: it holds no blocking-pool slot and joins no thread, so a writer still stuck at its 5 s bound is abandoned.
- **Files.** The trials path is walked from `/` by descriptors with every directory judged by its role; compression, samples and watched files use held descriptors, and watched files must be regular, owned by the workload uid and have one link.
- **Go bugs fixed.** Each is grounded in `internal/trial`: `streams.Wait()` (the pipe readers), the process join and the samples writer's close were unbounded after the teardown deadline (`run.go:427,431`, `samples.go:169-172`), and a blocking log write ran on the reader goroutine (`trial.go:339`); a successful scope kill counted as proof that every member exited (`teardown.go:32-43`); watched files were reopened by path and compared by size only, so a same-size replacement went undetected, and hard-linked and foreign-owned files were read (`output.go:104-127`); the spec was not validated, so a trial id reached `RemoveAll` and an empty or mismatched core and CPU list panicked (`trial.go:127-131,154,163`); `chown` and the trials root followed symlinks, `samples()` opened FIFOs and symlinks, and the trials path was checked only for the backend's search permission, so a state directory beneath a replaceable ancestor was accepted (`process.go:314`, `trial.go:131-146`, `identity.go:328-357`, `trialfiles/files.go:113-114`); preparation ran synchronously on the `Start` caller with no deadline, so a stuck write ignored cancellation and delayed rollback (`trial.go:168,230-264`); `USER_HZ` was hard-coded and CPU time could overflow (`process_linux.go:181`); concurrent `Stop` and `Wait` mutated shared instance state, since the lock covered only teardown against teardown (`run.go:398-409`). The full list is in the pull request.
- **Tests.** Each of Go's 111 test functions maps to Rust tests, or the pull request says why it no longer applies (`stop` consuming the handle replaces the repeated-stop test; launches are synchronous). The 440 Rust tests of the crate (the `hardware` feature excluded) run in 8.6 s under `cargo nextest` on Linux; `go test -count=1 ./internal/trial` reports 0.115 s. Real-process tests are named `real_process_*`. The VM check ran the `hardware` tests as root (10 of 10) and as a delegated user (8 of 8), plus the 2 tests of `tests/cached_errors.rs`, which refuses uid 0 and so ran as a delegated user only; after each run no `togi-*.scope` remained. Later commits change only error and report text and tests. The `hardware` binary has 12 tests: the one that runs every workload for twenty seconds needs real backends and was only compiled, and the unit test `a_privileged_run_hands_watched_files_to_the_configured_account` needs root and was not run as root anywhere. None ran on the writer's host, and the macOS target was cross-checked with clippy only, never run on a Mac.
- **Size.** 8,032 lines of library and 15,695 of tests (counted by splitting each source file at its `#[cfg(test)]` module: the module, `src/tests/`, `testing.rs`, `tests/hardware.rs` and `tests/cached_errors.rs` are tests) after the review fixes, against Go's 2,200 and 6,195. Against the base `c9d10ca`, the pull request changes 45 files of the crate, plus `Cargo.toml`, `Cargo.lock` and this log; no Go is removed.
- **Review findings fixed.** The first review round found 103 findings, all fixed in this pull request. The P1 defects: an unowned start whose reply could not be delivered, runner shutdown that ignored starts in progress, a sweep cancelled before it killed the scopes it found, a supervision or classifier panic that left no owner for the teardown, a watched read that blocked the runtime, a final watched append that was never read, unvalidated ancestors of the trials path, preparation on the runtime thread, a libc `setgroups` in `pre_exec`, and hardware tests that did not exercise the containment they claimed (a descendant sharing its launcher's group, a sweep with no live orphan, a predictable staging path). Review also caught places where the initial Rust implementation regressed from Go: a late first `wait` reported a finished trial as stuck, where Go starts the wait's deadline when `Wait` is called; the remaining lines of a polled chunk were classified after cancellation or the deadline, where Go checks both before every line; a watched read error dropped an accepted backlog without containment, where Go leaves the file undrained and reports containment; an oversized watched line's prefix was discarded, where Go keeps it; and a sweep whose grace observation failed skipped its scope kills, and a final verification failure replaced earlier ones, where Go kills regardless and joins every failure. A stress run under load in the same round found one more defect, which Go did not have: the kernel prints -1 as the process group of a task it is tearing down, the stat parser read it as unsigned, and a sweep or teardown that scanned a dying captured process reported false containment instead of a gone process. The rest were test and mapping gaps, now backed by tests that fail when the fix is reverted.
- **Second review round (C wave).** Seven more defects, all in the Rust port, fixed here. Go has no counterpart for the mechanisms involved (it has no runner shutdown, supervisor registry, abandoned scan, final re-read with a drained snapshot, classifier recovery or cached wait error), so none is a Go bug and none is a regression from Go behavior: a final watched re-read that ended unfinished kept the drained proof of an earlier poll; a sweep cancelled during its process scan dropped the cleanup of the scopes it had already listed, which Go does not do either way, since it returns a containment error at once when its context is cancelled during discovery (`sweep.go:39-46`), so finishing the bounded cleanup is a stricter Rust rule and cancelling before any scope is known still returns at once; a `/proc` scan whose caller was cancelled was not counted as abandoned, so a replacement could start beside it; runner shutdown tore supervisors down one after another and missed a supervisor that a pending start registered during shutdown; a handle dropped after the supervisor's last abandon check lost the report of its teardown; a supervision panic replaced the classifier panic that followed it; and repeated `wait` failures hid the kept error from `std::error::Error::source`, now pinned by `tests/cached_errors.rs` (feature `hardware`, real user-manager scopes, not run by the plain test command).
- **VM finding.** The first VM run of the new hardware tests caught a defect in their own cleanup helper, a Rust test regression and not a Go bug: stopping a stray scope exited with status 5 when the killed launcher's `--collect` had already unloaded the scope, and the helper reported that as a failure. It now accepts an already unloaded scope.
- **Third review round (D).** Mostly test gaps, now pinned: per-instance sampling under two watched floods, a task entry that is not a directory, sweep systemd commands that cannot run, the unwaited start and sweep reports, the shutdown deadline report, both panics in a dropped trial's report, a cached cancellation joined to a failed teardown, and a test owner guard that fails closed. One Rust diagnostic defect, not a Go bug: the stderr reports of an unwaited start or sweep and of an abandoned trial dropped the causes behind each failure, and a start failure printed its cause in its own text and again as its source. Each report now lists every failure with its causes once.
- **Not measured.** Isolated compile times against Go, and agent cost.

## Stage 3: tuner queries and forecast (#758, 2026-10-11)

`togi-tuner` gains the read side of the folded `State` ([#614](https://github.com/shgew/togi/issues/614), ADR 0059): `next` and `drain` composed from the group decision functions of G1 to G5, an owned `Projection` with the dashboard views, the phase plan and the BIOS profile, and `forecast` (G6). Against the combined G3 to G5 branch (PR [#799](https://github.com/shgew/togi/pull/799)) it adds about 2,100 lines of library files and 4,650 of test files in `crates/togi-tuner` (`git diff --numstat`), 97 `#[test]` functions and 3 property tests among them; the crate's 723 tests run in about 3.6 s under `cargo nextest` on Linux. No Go code is removed or changed. Compile times and the comparison with `go test ./internal/tuner` are left to the closing stage (#759).

- **Read-only queries.** `State::next(&self)` answers `Result<Action, NotReady>` where Go panicked on an uninitialised tuner; `NotReady` is `NotStarted`, `Poisoned`, `NoPhase(core)` or `NoAction`. `drain`, `project`, `forecast` and every view take `&self` and no event list, and doc tests pin that `next(&events)` and `project(&events)` do not compile. `replay` folds a journal into a fresh `State` and stops at the first event the tuner cannot follow. Property tests check at every prefix of scripted sessions that `next` is pure, answers the same twice and equals a fresh fold's answer.
- **Owned projection.** `project` returns an owned, serializable `Projection` (cores with their offsets, constraints, checking, cycle plan, search turns, hunt plan, phases, BIOS profile, R7 status, requirement and trial history) in place of Go's cached pointers and `projectionDirty` flag. The projection types are exported from the crate root; their modules are private. A test pins that a cycle start invalidates the projected checking, and the projection of a crashed session equals a fresh fold's.
- **Forecast.** Each premise (pass, all-pass, each named representative, unnamed, inconclusive) clones the `State` and folds synthetic events into the clone; Go replayed the journal per branch. Tests fold the journal after 100 and after 10,000 passes, forecasting a cell with no history, the open trial's own cell that holds those passes, and that cell after a clone was kept while the passes were folded. Each finds the same number of cells visited at both sizes; the first two also copy the same number of seqs, and the third copies at most 1,024 seqs per list a forecast clones, whatever the passes. The clones share each cell's seq list and each R7 segment's witnesses behind an `Arc`. An append to a shared seq list goes to an owned tail of at most 1,024 seqs, more than the 1,000 trials a step can require; the append that would pass that cap while a clone still shares the list copies it once into a list of its own, and a forecast's own copy appends past the cap without copying. Only an insert or removal inside a shared list copies it otherwise. The recorded host ranking is reused, a missing one is `Uncertainty::NeedsRanking`, and a hunt plan that recurs is found by comparing its sets, not by position.
- **Go bugs fixed.** T12: the stopped check looked only at the last event, so a `shutdown` or dead end followed by a `session.warning` forecast future work; a flag set by those two events and cleared by `config.loaded` replaces it. T13: the all-pass loop returned true after a completion error, a missing next trial or an uncertainty, as if every pass had run; `AllPass::{Complete, Diverged, Stopped}` now says which. `resume` consumed the hypothetical state it was handed, and `Trial.Complete` errors were dropped; the first is a clone and the second cannot occur because the workload is an infallible id.
- **Deviations kept.** `Run` keeps a `stopped` flag, not the design's stop seq and kind: nothing reads them. `core_limit` is `Option<Limit>` and is `None` for a core outside the topology, which would otherwise read as at the floor. The projection carries a `ConstraintView` of failure points and combinations, not the `Constraints` indexes. The Go forecast test of an intent for a core without a phase has no native twin: an intent that matches no scheduled trial is `FoldError::UnscheduledIntent`, so the test checks every prefix of a two-core session in which only one core has a phase instead.
- **Tests.** The Go tests of `forecast_test`, `dashboard_test`, `phase_plan_test` and the drain tests listed under G6 map as the pull request lists; where a Go test was half pinned by an earlier group (the cycle-plan half of `TestCrashRecoveryKeepsTheRunningPart`, the view half of `TestStoredRequirementSeparatesClassCountAndPart`), the other half is pinned by its own test. `just cover-rs` on the reviewed head listed 17 ranges no test reaches; 16 are triaged as defensive with the argument that excludes it (a guard on a sequence overflow, a loop bound, a fold of an event the same state just produced), and the review found the 17th, a carried pass shown on a hunt's member probe, reachable, so a test now pins it.
- **Review findings fixed.** Sixteen reviewers found no P0 or P1 defect. Two P2 code defects: a forecast premise that ended the open trial copied that trial's whole pass list, so the forecast's cost grew with the passes the cell held; and a `config.loaded` while a cycle trial was open showed the running cycle part with the new configuration's durations and lost its passes, where the trial's stored requirement still named the old ones (the running part now keeps the plan it started with until its trial ends). The first fix sent appends to a shared list to an unbounded owned tail, and its review found that a clone kept while passes were folded let that tail grow with them, so every later clone copied it; the tail is now capped as above. Six P2 test gaps were closed: every forecast test now checks that the state is unchanged, the retained inconclusive trial is compared on its load, condition, regime and activity, the R7 premises assert that no branch ends tuning, the hunt cut counts a change of trial length and an upcoming distinct set as new cuts, and the public hunt plan is checked for a carried member probe and for the corroborated core's single part.
- **Not measured.** Compile times, the comparison with `go test ./internal/tuner`, agent cost, and the forecast's cost on a long recorded session (the cost test counts cells visited, not seconds).

## Stage 5: `togi-hardware` (#767, 2026-10-11)

The `togi-hardware` crate ports `internal/hardware` ([#767](https://github.com/shgew/togi/issues/767)) and assembles the real machine: `open(config, state_dir, &HostLock)` returns the `togi_machine::Machine` of the SMU driver, the PM table reader, the `togi-detect` kernel log, the `togi-trial` runner and a monotonic clock, and `diagnose` is the read-only check set behind `togi doctor`. `Grub` implements `togi_tuningboot::{Environment, Bootloader}` over `grub-editenv`, and `reboot` asks systemd for a plain reboot, both through `togi-command`.

- **Shape.** The host is the preflight of `runtime.md` as data: `Step` and `CheckName` enums, an `Outcome` that is either made or `Skipped` with a typed reason (`NeedsRoot`, `NeedsIdentity`, `NeedsOtherChecks`), and one `Account` that is either resolved to a `BackendIdentity` or refused with its cause. One `Arc<Mutex<Driver>>` serves the `Smu` face and the host's checks, and one `Arc<Mutex<Runner>>` serves `Machine::trials` and the `systemd_run` probe, so a process has a single trial runtime thread. `Mprime::new` and `Ycruncher::new` are fallible, and `Error::Backend { backend, source }` keeps the constructor's error. `Trials::samples` reads the trial's samples before the lock guard is released, because a guard cannot back the borrowing iterator.
- **Go bugs fixed.** `grub-editenv` ran with no deadline and unbounded output; it now has 10 s, a process-group kill and a 64 KiB cap per stream (stdout and stderr), so a hung command cannot hold the host lock. Preflight called `preflight(true)` even when the `root` check had failed, so a delegated caller read the PM table, the readback and the CCD fuses and probed systemd before its refusal reached the journal; those checks are now refused without root, before any access. `Diagnose` started the PM reader before the identity checks and discarded every check already made when the BIOS read failed; the reader exists only once the driver validated, and the failure keeps `ran` and `skipped`. Checks gated on a failed identity disappeared from the journal in `run`; they are recorded as failed checks with the reason. The ranking parsed with `Atoi` into a native int whose comparison could overflow; the value is a checked parse and a value beyond `i64` is an error naming the CPU. The backend account error was kept apart from an identity that was passed on regardless; an unusable account provides no identity.
- **Rust regressions caught in review.** The first draft built a second throwaway `Runner` for the probe, so `doctor` and `run` each started two runtime threads; one runner is now shared. `diagnose(config, recorded, privileged)` trusted its boolean, so a caller asking for privileged checks as a plain user constructed the full driver and the checks read the mailbox, the SMN and the PM table; the request is now combined with the effective UID before the driver exists, and a request without root, like root without a request, chooses identity-only inspection. The effective UID is a private seam, so the tests do not depend on who runs them.
- **Final `togi-trial` interface.** `Error::Panicked`, `Error::Stuck`, `InvalidTrial::{CoresForOneInstance, UnrepresentableDuration}`, `PrepareError::{TimedOut, Busy, Spawn, Vanished}` and the `togi_trial::Error` now exposed in the seam error's source chain need no new mapping: the crate matches on none of them, and `outcome` formats a probe error with its whole source chain, so each reaches the `systemd_run` check's detail. Three tests pin that for the panicked, stuck and vanished runtime.
- **Spec changes.** `runtime.md`: preflight item 2 refuses the root-needing checks without root and records a check not made as failed with its reason; item 7 stops `run` and `doctor` before preflight, with exit 1 and the typed error naming the CCD and the core, on a core id outside 0–15 (the spec made it a preflight record); the diagnosis treats privileged checks as a request that effective UID 0 must also grant; the `doctor` row keeps the checks already made when the BIOS context cannot be read; `grub-editenv` is bounded. The behaviors that already matched the spec (the 30 s watchdog gate, the check order, one backend-user account) are unchanged.
- **Tests.** Each Go test of `internal/hardware` maps to Rust tests, or the pull request says why it does not; the four privilege tests, the five `real_process_*` tests of the `grub-editenv` runner, the `reboot` tests and the three probe-error tests have no Go counterpart. The 101 tests run in 0.33 s under `cargo nextest` on Linux; `go test -count=1 ./internal/hardware` reports 0.005 s. The `hardware` feature adds one integration test, `diagnosing_leaves_every_offset_unchanged` (`TestHardwareDiagnoseLeavesOffsets`), which takes the host lock, reads every offset before and after a privileged diagnosis and needs the real SMU. It compiles in clippy with all features and was not run.
- **Size.** 1,548 lines of library and 2,299 of tests (the unit test modules, `src/tests/` and `tests/hardware.rs`) against Go's 467 and 877. No Go is removed or changed.
- **Not measured.** Compile times against Go and agent cost. Nothing ran on real hardware, and nothing ran on a Mac: the `aarch64-apple-darwin` check is clippy from Linux, which covers the `Unsupported` path.

### Forecast cost, against Go's

The same shape as "Go `Forecast` cost" above. A throwaway program kept outside the repository, built `--release` against `togi-tuner` and `togi-journal` at `113b73ee`, read a journal with `Recording::read`, timed three full `replay` folds, then, for 800 prefix lengths drawn from `StdRng::seed_from_u64(1)` and sorted, timed the fold of that prefix alone and one `forecast()` on the state it folded to. It calls nothing else on the state. One process, one batch, one run per prefix; 8.94 s of wall time, 35.0 MiB at peak (`VmHWM`), at a load average of 2.18 when it started and 2.00 when it ended.

- **Session.** Rust reads no Go journal, so the session is not Go's: `target-r7-request-gap`, holdout seed 110, run by the stage 4 simulated session on its unmerged branch (Rust-written, 27,801 events, 1,941 trial intents, 233 boots, stopped after one clean cycle). Go's figure is the same scenario and seed but a Go session of 40,592 events and 2,266 intents. Not like for like: a different implementation of the session, with a different event mix and length.
- **Full fold:** 39.64, 39.08 and 39.05 ms; 1,426, 1,406 and 1,405 ns per event (Go: 191, 194 and 174 ns per event on its journal).
- **`forecast` per prefix, 800 prefixes:** mean 0.3563 ms (standard error 0.0141 ms), median 0.2008 ms, min 0.0001 ms, max 4.2018 ms at 24,460 events; the mean over the last tenth of the session is 0.9000 ms (71 prefixes). The fold of the same prefixes averaged 10.5095 ms (max 38.7036 ms); `forecast` averaged 0.034 times its fold (Go: 2.02 times). Branches per call: median 0, maximum 5.
- **Whole-session cost.** Calling `forecast` at every prefix would cost 27,801 × 0.3563 ms ≈ 9.9 s of one core (standard error ≈ 0.4 s, a sampling estimate), against Go's ≈ 157 s on its longer session. Per call, the Rust forecast's mean is 0.09 times Go's and its median 0.10 times. The session ends stopped, so `forecast` on the full journal returns at once (0.0001 ms, no branches) and is not the dashboard's cost on a running session.
- **The fold.** On these two journals the Rust fold costs about 7.6 times Go's per event (means of the three folds), and its cost per event grows with the journal: the fold of the sampled prefixes averages 66 ns per event in the first tenth of the prefixes and 1,262 ns in the last, so a full replay costs about quadratic time. The cause is in the tuner, not in the comparison: `config.loaded`, `profile.change`, `checking.chain` and `checking.step` rebuild the open checking cycle over the whole evidence ledger on every call, and `config.loaded` and `profile.change` also rebuild the exposure table over it. They are 3.5% of this journal's events and 81% of its fold time, and the ledger's distinct classes and cells grow with the session (96 classes and 279 pass cells early, 457 and 1,108 at the end). This breaks #638's cost rule; the fix is [#811](https://github.com/shgew/togi/issues/811), which logs its own before and after.

## Stage 3: fold cost (#811, 2026-10-12)

The closing measurement of #759 folded a recorded 27,801-event session (1,941 trial intents) and found the fold's cost per event growing with the journal position: the cumulative mean per event rose from 66 ns at the start to 1,262 ns, so a full replay took about quadratic time. Four handlers caused 81% of the fold time while being 3.5% of the events: `config.loaded`, `profile.change`, `checking.chain` and `checking.step` each rebuilt the open checking cycle's whole schedule and recounted every class of it (about 230) over all its cells, and `config.loaded` and `profile.change` also recomputed the exposure of every class of the ledger, `set_backend` doing so twice per `config.loaded` even when no backend path changed. The cost follows the ledger's distinct classes and cells (96 classes and 279 pass cells early, 457 and 1,108 at the end), not the raw events, but each rebuild consulted the whole plan and ledger where the event changed one chain, one profile or nothing, against #638's rule that a step costs at most the distinct evidence a rule consults.

- **Exposure.** `Evidence::set_backend` returns whether the active package changed and recounts exposure only then, and only for the classes of that backend. `set_checking_profile` recounts the classes that can have exposure under the new profile or have it now. Each class keeps `reach`, the deepest offset per core among its pass cells, updated when a pass cell is added and rebuilt when `reset_core` drops named cells: no pass cell covers a profile `reach` does not cover, so a class whose `reach` does not cover the checking profile and that has no exposure is not looked into. The per-workload sums move by the delta of each recounted class. `reset_core` keeps the full recount: it drops whole classes and the idle failures that floor every all-core R6 class, and no cheaper exact rule was proved for it.
- **Open cycle.** `rebuild_cycle` is replaced by `replan`, which builds again only the steps a change reaches (the step whose chain changed and the later steps of the same workload, whose quotas add to it, or all steps for a new cycle or new durations), keeps the counts of classes the new plan shares with the old, counts the classes it adds and forgets the ones it drops. `config.loaded` replans only when a duration a plan is built from changed and recounts only the classes of a backend whose package changed; `profile.change` recounts the classes with a count or with cells that can cover the new profile; `checking.chain` and `checking.step` count only the classes their parts add. `refresh_cycle`'s incremental pattern is kept, and a trial end now looks its class up directly instead of scanning every quota class of the plan. `Profile::covers` and `within` compare core counts instead of collecting two core sets per call, with the same results.

## Stage 4: `togi-session` (#742, 2026-10-12)

The `togi-session` crate ports `internal/session` ([#742](https://github.com/shgew/togi/issues/742)): the tuning session. `run` takes a `RunInput` through startup, the tuning loop and the cleanup every exit shares and hands the journal back in `Ended` with a `ResumeCapsule`; `reset_core` and `reset_all` are the two journal commands; `prepare` is the Rust home of `carry.Prepare`. About 6,700 lines of library and 15,000 of tests. The 342 tests run in about 10 s under `cargo nextest` on Linux; two whole-session sweeps that kill the run at every durable event dominate it at about 9 s each, in parallel; the other tests finish within 2 s.

- **Go bugs fixed.** Session phase A: the applied slot changed before its readback; MCE dedup by joined text; topology indexed by vector position; an unchecked raw set; zero-all before shape validation; another trial's progress affecting the open trial; the `errDeadEndEvidence` sentinel; a silent gated emergency; deeper writes over unknown peers; an out-of-range first-write register entry. B1: the session id allocator ignored archives; `reset` appended a `shutdown`; `kernelDeadDetail` was not durable; a cancelled third retry dead-ended; a no-evidence dead end kept kernel retries; a crashed pstore or ended seam was downgraded to a warning, and its warning preceded `crash.detected`; the idle profile was built from an incomplete topology; pending dead-end causes and saved-entry scanning; an Alone+Many trial wrote the wrong core's target; `trial.end.core` was missing on some trials; state published after the journal closed; no emergency after a machine crash; a crash in `validate_smu` was swallowed. Pre-review fixes: proof-preserving sweep and check order, the failed-sweep containment latch, refusal of changed cores before appends (pending dead-end actions included), a durable recovered MCE classifying an interrupted trial after the kernel forgot it, reset membership from the recorded topology, the reset-all compatibility verdict, indexed MCE lookup. B2: the warm-resume verify compared tuner panic text (now a typed `NotReady`); `reset --all` spent the journal on some paths only; an event-log write error was never reported (now `SessionError::Log`); recovery queued an idle failure for a crash on an alone trial with nothing in flight, which the tuner cannot fold.
- **Pre-review Rust-only defects fixed before first push.** A crash-terminal emergency stop touched the SMU at the first crash; sweep proofs and the failed-sweep containment were retained only after the fallible check append; containment was latched after cleanup, not before; a durable fold rejection neither latched nor cancelled the appender and zeroed by the ordinary path; a resumed changed core set was refused after appends; recovered durable MCEs did not classify interrupted trials; reset membership came from the current topology, not the recorded one.
- **Carry and resume.** `prepare(dir, build, boot, now, context, defects)` judges the live journal's build from its first line, archives a transition, a reset-boundary journal or a BIOS change, settles the carry markers and selects the carry from the archives; it needs `StateDir::live_build`, `StateDir::archived_recording` and `Journal::dir` in `togi-journal`, all additive. `ResumeCapsule::verify` also proves the published state document round-trips through JSON and equals the cold fold's, and `ResumeCapsule::publish` writes the document a crashed `OnFinish` run left unwritten.
- **Dead end at CO 0.** A failure point at 0 is reached by every profile but all zero, so the restoration kept the baseline and held offsets of the other cores, and their deepening writes were refused: the run ended in `Profile(Refused)` with no shutdown, on a dead end met in the loop and on a pending one finished on the same boot. Go's `restore` computed the same target. The restoration now zeroes every core while such a point stands; a later run stops at the same dead end cleanly without an SMU write.
- **Undecodable archives.** An archive this build cannot decode supplies no carry evidence: the walk ends before it, and a marked source that cannot be decoded carries nothing. An archive that cannot be read still fails the preparation.
- **Not measured.** Compile times against Go and the comparison with `go test ./internal/session`.

## Stage 7: `tools/facts` (#819, 2026-10-12)

The `togi-tool-facts` crate ports `tools/facts` ([#819](https://github.com/shgew/togi/issues/819)): `togi-tool-facts STATE-DIR OUTPUT` extracts the privacy-safe trial facts of a copied state directory with `togi-tool-trialfacts` and replaces the output atomically, printing `extracted N facts`. The library is `generate`; `main.rs` is a clap parser, the stdout line and the exit statuses (0 on success, 1 on a failed extraction or write with `togi-tool-facts: <error>` on stderr, 2 on a usage error).

- **Atomic write.** `generate` calls `togi_tool_trialfacts::write`, which writes a temporary file in the output's directory, syncs it and renames it over the output; the temporary file is a `NamedTempFile` and is removed on every error path. A failed extraction never reaches the write, so an existing output is untouched. There is no second copy of this logic in the tool.
- **Go bugs fixed.** Go's `generate` closed and renamed its temporary file without syncing it, so after a crash the rename could be durable while the data was not, replacing the committed extract with an empty or truncated file; `togi_tool_trialfacts::write` syncs before the rename. Go's `generate` also created the temporary file before extracting, so a bad source left a short-lived file in the output's directory and a missing output directory was reported before a bad source; Rust extracts first.
- **Design call.** `togi_tool_trialfacts::extract_dir` takes the state directory's writer lock, which creates a missing directory and every ancestor, so a mistyped source would leave stray directories where Go's read-only `facts.ReadDir` created nothing. `generate` refuses a state directory that is not an existing directory before extracting (`read the state directory <path>: …`), and nothing is created.
- **Recipe.** `just facts-rs STATE-DIR` runs the Rust tool next to the Go `facts` recipe and writes `tools/bench/facts/target.jsonl.gz`; it is a new line, and the Go recipe is unchanged ([#642](https://github.com/shgew/togi/issues/642)).
- **Tests.** 12 tests run in about 16 ms of test time under `cargo nextest run -p togi-tool-facts`, against 2 ms for `go test -count=1 ./tools/facts`. About 80 lines of library and 400 of tests, against 45 of Go and 130 of tests. The fixture builds a journal in memory and dumps it to disk.
- **Not measured.** Compile times against Go, agent cost, and the run on a Mac. No Go code is removed or changed.

## Stage 4: `togi-simrun` (#743, #741, 2026-10-12)

The `togi-simrun` crate ports `internal/simrun` ([#743](https://github.com/shgew/togi/issues/743)). `simulate(SimInput)` runs a session on the simulator:

- each boot runs `togi_session::prepare`, then `togi_session::run`;
- after a crash it reboots the simulated machine and resumes;
- it returns when a run ends without a crash, or after `max_boots` boots.

The state directory is in memory (`MemFs`) or on disk. Both publish `state.json` only when a run ends or, after a crash, from its capsule; the disk mode first published it after every event, about 300 MiB of renames for one default session, until [#868](https://github.com/shgew/togi/issues/868). `Replay::Warm` resumes from the crashed boot's capsule and `Replay::Cold` folds the journal again. Both modes verify the capsule against a fresh fold. An observer sees every appended event and can stop the run (the session calls it through `RunInput::on_append`, once per event after it is durable, so it works with either persistence) or arm the simulator's faults; it replaces Go's `Until` and `Wrap` journal wrappers.

The crate also holds the tuner's simulation tests ([#741](https://github.com/shgew/togi/issues/741)): `forecast_sim_test.go` and `memo_test.go` become `tests/sim/forecast.rs` and `tests/sim/memo.rs`. They need whole simulated sessions. `togi-tuner` cannot take `togi-simrun` as a dev-dependency, because the cycle would build a second `togi-tuner` whose types do not unify with the first.

Size: about 750 lines of library, 200 lines of unit tests and 4,600 lines of integration tests. The crate's 80 tests run in about 22 s under `cargo nextest` on Linux. The memo recomputation and the default-machine memory-against-files checks take 15 to 21 s each.

- **Go bugs fixed.**
  - Cold-boot verification was a silent no-op; Rust verifies the capsule in both replay modes.
  - Memory mode wrote disk files.
  - A JSON round trip worked around aliasing.
  - A failed log flush was discarded. Rust flushes the caller's log when the simulation ends, and a flush failure is `SimError::FlushLog`.
  - A capped run was classified by matching `ErrBootCap` in the error chain. In Rust, a verification or publication failure on the last boot is an error and never `Capped`.
  - A later process rebuilt the machine from the journals alone and lost three things: the pending machine checks, the reset reason the next boot reports, and the time between the last event and the crash. A capped simulation now leaves `machine.json` (`togi_sim::Persisted`), and `resume_simulator` continues from it.
- **Defects found in other crates.**
  - `togi-journal` committed whole-millisecond `mono` to disk but kept nanoseconds in memory, so a capsule diverged after a reopen. Fixed in [#804](https://github.com/shgew/togi/pull/804).
  - An `OnFinish` run that crashed published no state document. Fixed with `ResumeCapsule::publish`.
  - An undecodable archive blocked carry selection. Fixed in `togi-session`.
- **Review fixes before merge.**
  - A crashed boot's other errors, such as a failed log write, are `SimError::Failed`; they were dropped.
  - The observer kept no events after the caller's log failed.
  - `machine.json` was removed before a continuation made progress.
  - An in-memory simulation's next session read the last trial's samples of the earlier session.
  - A persisted machine decoded from positional arrays.
- **`togi-sim` changes.** `Simulator::persisted`, `Simulator::restore` (objects only) and `Simulator::forget_last_trial`. `set_samples_dir` keeps the last trial's samples when the directory does not change.
- **Not ported.** Go's older-schema carry cases and the "known events carry past an unknown kind" case. Rust has one schema and refuses unknown kinds; the remaining property, that an undecodable archive is archived and carries nothing, is pinned. The table below gives the Rust tests for each Go test, or the reason a Go test has none.
- **Not measured.** Compile times, and the comparison with `go test ./internal/simrun`.

## Stage 7: `tools/modelcheck` (#816, 2026-10-12)

The `togi-tool-modelcheck` crate ports `tools/modelcheck` ([#816](https://github.com/shgew/togi/issues/816)): 612 lines of library and 698 of tests, against Go's 305 and 301. No Go code is removed or changed. It is a library for `tools/fit` and `tools/bench`.

- **Two ways in, one verdict.** `check(machine_path, &definition, &mut Extracts)` and `check_records(machine, extract, &Model, &records)` return a `Check` for a report (`report` prints it; `Check` and `Group` serialize). `Checker::new(&Model, &records)` groups the evidence once; `Checker::accepts(&Model)` answers a search's candidate without interval work, and `Checker::groups` / `Checker::check` fill in each group's mean probability, interval and flag. A test pins that `accepts` and a report's `ok` agree, and a property pins that a count is inside the interval exactly when `p` is inside the group's precomputed bounds.
- **The predictor is `togi_sim::Model`.** Go's `Predictor` interface, which a `Machine` and a `Predictor` both satisfied, is gone: the model already owns `failure_probability`. A model of another shape than the checker's is a `ShapeError`, never a wrong verdict.
- **Typed evidence.** A group is keyed by BIOS context, `TrialClass` and a `TargetOffset` depth, not by a JSON string; the `Kind` field is gone because only trials are grouped, and a trial that is neither pass nor failure, or a kind that is neither trial nor idle, cannot be written in a `TrialFact`. Groups come out ordered by context, workload, loaded cores, duration and depth. Facts are validated against the model: one offset per core, a loaded core that exists, a nonzero duration, each refused as `Error::InvalidFact` naming the session and sequence.
- **Log-binomial coefficients.** std has no `lgamma`, so `ln C(n, k)` comes from a Neumaier-compensated table of `ln(i!)`; `Binomial(10000, 0.5)` still gives `[4871, 5129]`.
- **Own formats.** A report line lists loaded cores as `0,1` and prints `mean_p` as `{:.6e}`; `Check` serializes `interval` as `{low, high}`, the class as `regime`, `workload`, `cores`, `duration_s` and the status as `ok` or `flagged`. Go's `testdata` fixtures (a Go-written extract with a workload outside the catalog) are replaced by fixtures the tests write with `togi_tool_trialfacts::write`.
- **Go bugs fixed.** None found. The reset check, group threshold, bounds bisection and interval rule are as in Go; `docs/benchmarking.md` already describes them, so no spec changes.
- **Tests.** Every Go test maps to a Rust test or a stated reason (mapping in the pull request). `go test -count=1 ./tools/modelcheck` took 0.006 s (11 tests); `cargo nextest run -p togi-tool-modelcheck` ran 26 tests in 0.04 s on a built tree.
- **Not measured.** Compile times against Go, and agent cost. Not run on a Mac.
- **Review findings fixed.** Groups were keyed by class and depth only, so a machine that declares no BIOS context pooled trials recorded under different contexts into one group, labelled by whichever fact came first; the context is now part of the key, as in `docs/benchmarking.md`. A missing or corrupt facts extract reported "load replay oracle: ..." although no replay is involved; `Error::ReadExtract` now names the extract read and keeps the `ReadError` as its source.

## Stage 7: `tools/forecast` (#817, 2026-10-12)

The `togi-tool-forecast` crate ports `tools/forecast` ([#817](https://github.com/shgew/togi/issues/817)): the library `tools/bench --forecast` (#823) writes forecasts with and `tools/stats --forecast` (#820) scores them with. It is the pure part: the anchor, a run's outcome after it, the summary of an ensemble, the committed record and the score of the real run. It starts no simulation: the runs, their seeds and their order belong to the caller, and every function is a pure function of its inputs, so the record does not depend on how the runs were scheduled. It needs `togi-journal`, `togi-machine`, `togi-sim` (the reboot time the bias note states) and `togi-tuner`, and not `togi-session`: this build's ruleset is `togi_tuner::RULESET`.

- **API.** `Anchor::of(dir)` and `Session::anchor_at`, `read_dir(dir, from)` (read-only, no lock), `after(sessions, anchor) -> Outcome`, `Record::new(...)`, `Record::write` and `Record::read`, `Record::score(sessions) -> Score`, `metrics` and `summarize`. Statuses, metric kinds, placements and flags are enums; a profile is `PerCore<ObservedOffset>`, so a run's cores are named by id and a forecast and a run over different cores are refused by id, not by count.
- **Design calls.** The anchor hash covers the journal lines as the file holds them, kept as one running SHA-256 prefix per event, so a build that later encodes events differently still scores an old forecast; a session built in memory hashes the events' own encodings, which are the journal's bytes (a test reads a real simulated journal back to prove it). The replay rule is `Build::verdict(Operation::Replay)` on the session's build; a session keeps its `Refusal`, so `NotReplayable` names the dimension (schema or ruleset) and both values. The record is the Go field set with `evidence` added, `outcome` nested in each run and `profile` and `cores` objects of core to value; it is the Rust record, which `Record::read` holds to that layout and so refuses a Go-written forecast (the Rust build reads nothing the Go tools wrote). The counting rules run against a small private `Replay` seam, so they are pinned without a journal the tuner would accept; the real tuner runs in the whole-session tests, one of which pins its checking profile against the journal's last `profile.change`.
- **Go bugs fixed.** A fold error of the journal state or the tuner was dropped, so a damaged session scored from a half-folded profile; it is an error naming the session (`after::a_journal_that_does_not_follow_itself_is_a_fold_error`, `a_journal_the_tuner_cannot_follow_is_a_fold_error`). Scoring compared only the number of cores, so a forecast and a run over different core sets of one size scored against each other's columns; it compares the sets (`score::a_run_over_other_cores_than_the_forecast_is_refused_though_their_count_matches`). The percentile of a metric without values was `NaN`; it is `None` (`summary::without_a_concluded_run_hours_have_no_range`). A forecast of one evidence epoch scored against a run of another without a flag; it carries `Flag::EvidenceEpoch` (`score::a_dirty_forecast_and_another_ruleset_or_evidence_epoch_are_flagged`). An unknown run status was a late error in `Summarize`; it cannot be decoded (`record::a_record_with_an_unknown_status_is_refused_on_reading`). Go ignored unknown keys in a record, so a misspelled `hours` read as no concluded runs; the Rust record refuses them (`record::an_unknown_key_is_refused_in_every_object_of_a_record`). Go's decoder already rejected an array for a struct, which serde's derive would accept by position, so every object of the Rust record is object-only (`record::a_correctly_sized_array_is_refused_for_every_object_of_a_record`).
- **Not ported.** Go read a session the strict reader refused through a lenient history reader and called it not replayable; the Rust build has one reader, so a journal that does not decode is an error naming the file (`files::a_journal_that_fails_the_readers_checks_is_an_error_naming_the_file`), while an archive older than the anchor's session is skipped unread. No Go journal is read.
- **Tests.** 75 tests run in about 6.2 s of test time under `cargo nextest run -p togi-tool-forecast`, against 0.18 s for `go test -count=1 ./tools/forecast`. Almost all of it is the endless-run test (`simulated::an_endless_run_scores_as_the_cycles_one_run_though_it_crashes_after_concluding`, about 6.1 s), the port of Go's `TestAfterScoresAnEndlessRunAsACyclesOneRun` on `togi_simrun::simulate`: a 16-core history simulated to its first `crash.detected`, then two copies resumed on a near-limit-failing machine with another seed, one with `--cycles 1` and one without a limit that checks one more cycle and crashes in it; the second scores exactly as the first. The two-core cycles-2 test (0.2 s) stays: it pins the real tuner's checking profile against the journal's last `profile.change` and the session baseline. About 1,230 lines of library and 2,310 of tests, against Go's 615 and 608. No Go code is removed or changed.
- **Not measured.** Compile times against Go, agent cost, and the run on a Mac.

## Stage 6: `togi-watch` model, history and words (#833, 2026-10-12)

The `togi-watch` crate begins with the model of the `togi watch` dashboard ([#833](https://github.com/shgew/togi/issues/833), part of [#641](https://github.com/shgew/togi/issues/641)): `model`, `history`, `words` and the `screen` seam the loop and the frames share, with no terminal output. It ports `model.go`, `snapshot.go` and `history.go` and the word tables of [#565](https://github.com/shgew/togi/issues/565): 3,707 lines of library and 4,921 of tests against Go's 1,962 for those three files and 1,079 for their tests (`snapshot_test.go`, `history_test.go`, `accessors_test.go`), with the Go package unchanged. 119 tests.

- **Shape.** `Model::fold(&Event)` takes each event once, in the journal's, the tuner's and then the watch's own state; `snapshot()` is a `Copy` struct of borrowed views, built once per change from the tuner's `project()` and `forecast()` and cached until the next fold. Go projected the whole journal for every frame. A fold the journal or the tuner refuses makes the model a problem state that keeps the error, so a frame has one thing to say. `words(kind)` is an exhaustive match over `EventKind` that says for each kind whether the log lists it and how its history line, log tag, compact outcome and detailed phrase read, so a new event kind does not compile until it is worded; a test pins the silent kinds. The frames, the narration and the loop read the model and `words`; none of them reads the journal.
- **Native, not Go.** The model follows the native journal: no record-only trials, so no `record` tag and no `signal` or `tail` entry fields; profiles are keyed by core id, so the position-versus-id handling of sparse core ids is gone; `Regime`, `Signal` and `WorkloadId` are closed enums, so the text fallbacks for unknown values are gone; a core's solo limit is the tuner's, not a second map kept by the watch, so a core that exited without a pass has none, and its search exit has no solo limit line or phrase either. A core's move with no history line of its own is tagged in the log by the phase it enters (`step`, `room` or `limit`), so a core entering its search at the start of a session is no longer tagged `limit`, and its phrase says it starts its search, not that it starts over. With record-only trials gone, no crash line carries a merge key, so Go's refold of a recovered record-only crash line into the line before it is not ported. A `hold` decision, which only the native tuner makes, has the tag `hold` and a history line. History facts stay raw: the frames escape, as the model does not know the terminal.
- **Go bugs fixed.** The view of a trial a crash left unrecovered was built with no events, so its start and partial flag were never set and the recovery frame could not tell a part from a full load; it is built as the running trial's view is.
- **Defects found before review.** Coverage found that the cycle's steps were never recorded from `checking.cycle`, so a step line never named its regime; the steps are folded now and a test pins the line.
- **Review findings fixed.** Round 1 found one P2 code defect: while a rerun ran, the step checking resumes at was read only from the forecast between trials, which the tuner leaves empty while a trial is open, so the step fell back to the plan's current step and did not skip the steps the tuner records only chain endings for; it is now read from the pass branch while a trial runs, as Go read it from its if-pass branch, and a test drives reruns and compares the step named with the next cycle trial's. The other findings were tests that did not pin what they named (the unrecovered crash's start and partial load, a later boot ending an earlier recovery, the idle hold released by a later boot, refolding after a snapshot, a tuner refusal, the session activity, the roles of a parked group's members, decision tones and log tags), an unused `signal` entry field, `_` arms over domain enums, a search exit with no pass worded as a solo limit, and a core's first move into its search, which the log tagged `limit` and the phrase called a start over: it is now tagged `step`, and its phrase says the core starts its search.
- **Tests.** The Go tests of `snapshot_test.go` and `history_test.go` map as the pull request lists. The tests of `story_test.go`, `narration_test.go`, `cycle_resume_test.go` and `r7_status_test.go` that assert a model fact (the idle hold, the past-end clock, the unrecovered crash, the resume step, the R7 top requesters) are ported here; those that assert wording wait for the narration ([#835](https://github.com/shgew/togi/issues/835)). ## Stage 6: `togi-watchtest` (#834, 2026-10-12)

`togi-watchtest` is a dev-dependency-only crate that builds the simulated session journals the watch tests read: the dashboard's frame tests, replay and stage 7's status tests. It replaces Go's `frames_test.go` helpers and the gzip recordings in `internal/watch/watchtest`, which Rust never reads.

- `Scenario` names the 18 watch golden scenarios that have a journal. `Scenario::events()` cuts one from a `Base` simulation. Each of the 9 bases is simulated once per process (`OnceLock`); `Base::simulate()` runs one afresh and `Scenario::events_from` cuts from it.
- `simulate(machine, config, until, stop)` runs `togi-simrun` in memory. Every journal names `build()`: version `0.0.0`, no revision, and the tuner's current ruleset and evidence epoch, so a release's version bump changes no frame. `until` is optional, and without it no observer runs.
- `cut_at`, `cut_when`, `cut_trial`, `cut_passed_trial`, `cut_passed_checking_trial`, `hunt_with_unconfirmed_profile` and `before_crash_detected` are Go's cut helpers, returning `Result` in place of failing the test.
- `install(dir, scenario)` writes `events.jsonl` through `togi-journal`'s writer, one open journal per boot, and returns the session's `Build`. A directory that already holds a journal is refused: the writer would append the scenario after it.
- `cycle_completed_by_rerun()` is Go's fixture of the same name, built by answering the real tuner's `next()` with no simulator.

Where the Rust simulator differs from Go's, a scenario is cut by the state its name claims, not by Go's event rule. `between` cuts after the first passed checking cycle trial: the first passed checking trial of the default session is a rerun. `unconfirmed` uses seed 43: Go's seed 30 never leaves a BIOS offset unconfirmed in the Rust simulator, and a scan of seeds 1 to 60 found one in seed 43 only.

The later-hunt base runs once, through three clean cycles. Go simulated six cycles twice: once to find the first checking trial of cycle 4, then again with the burst of crashes scripted from that trial on. Trials before the burst run alike either way, so the burst's start is pinned (trial 1887) and the burst's own journal is checked to show it; three cycles reach the same hunt, and the `hunt-bios` cut is byte-identical to the six-cycle one.

`deadend` is a journal the runner writes, not Go's synthetic event. Go appended a `no_evidence` dead end a minute after an R7 checking trial started, with no cause, beside a trial still running. The Rust runner checks for a dead end only after a trial ends, and every `no_evidence` dead end cites its evidence. The `DeadEnd` base runs the default machine and makes its mprime backend go missing once the first R7 checking cycle trial has started: that trial ends, the next mprime trial cannot start, and the session records the dead end citing the `backend_missing` end of the trial that could not start.

- **Measured.** Against `c9ba3004`: 1198 lines of library (with the manifest) and 803 of tests, none removed, next to Go's 441 test-helper lines (`frames_test.go` lines 27-336, `watchtest/fixture.go`, and the two fixtures of `cycle_resume_test.go`), which built journals and pinned nothing. ## Stage 7: `tools/fit` (#818, 2026-10-12)

The `togi-tool-fit` crate ports `tools/fit` ([#818](https://github.com/shgew/togi/issues/818)): a command crate, a library of 2,708 lines and a clap `main.rs` of 84, against Go's 1,934 lines of library and command; 2,939 lines of tests (61 tests) against Go's 1,973 (37 tests). No Go code is removed or changed; the recipes `fit-rs`, `fit-shared-voltage-rs` and `forward-rs` sit beside `fit`, `fit-shared-voltage` and `forward`.

- **Determinism across threads.** Every search step builds a vector of candidates and scores them with `par_iter().map().collect()`, so each result has its own index; the winner is then picked by a sequential fold with a strict `< score - 1e-9` test, in candidate order. A score sums its observations in index order on one thread, and no float is summed across threads. The joint candidates, the prefix fits of the forward check and the ensemble's members use the same index-slot pattern, and the first error is taken in index order; every fit runs to completion after a failure, so the error reported does not depend on which thread failed first. `--jobs` builds a pool of that size around the whole run (Go's `--jobs` bounded only the whole fits). `tests/fit/determinism.rs` runs one ensemble with its forward-chained check, and the shared-voltage anchor, on explicit pools of 1, 2 and all CPUs and compares the machine files, the reports and the forward rows; replacing the in-order observation sum with a rayon `sum` fails both.
- **Design calls.**
  - The machine being fitted is a `MachineDefinition`, rebuilt into a `Model` for each candidate; a candidate the model refuses (an overflowing rate) has infinite loss, so a search never keeps it, and the final machine is rebuilt with the error returned.
  - `Likelihood` is one struct with the optional shared-voltage terms (the threshold prior and the named-core failure share) instead of Go's embedded `voltageLikelihood`. Here every step minimizes the same objective, which fixes a Go bug (below). The anchor's likelihood on the committed extract is unchanged to 17 digits.
  - The bootstrap draws come from `StdRng` seeded `seed + n`, so refits 1 to 8 differ from the committed files; machine files are the simulator crate's own encoding.
  - Facts are typed: a trial's workload is in the catalog, offsets are in range and a failure always names a signal, so Go's checks for those and the "failure without a signal is skipped" rule are gone; a BIOS context with an empty field is kept as is, which drops Go's "every field set" requirement of the anchor.
  - `togi-tool-modelcheck` supplies the checker. Report lines, the elapsed times (printed by `main.rs` after the report) and the notes follow Rust's formats; `docs/benchmarking.md` has a section on the differences.
- **Go bugs fixed.** The anchor's shared steps (hazard shape, flat, idle, limit-rate shift) called Go's embedded raw `score`, without the threshold prior and the named-core term, while the voltage steps, the constrained rate search and the convergence test (`previous - score < 1e-5`) used the full objective. A shared step could therefore lower the raw loss while raising the measured objective, and the sweep then stopped early. Every step now minimizes the objective the sweep measures; `the_shared_steps_minimize_the_objective_the_anchor_sweep_converges_on` fails if a shared step reverts to the raw one. The committed extract's anchor likelihood is unchanged.
- **Measured.** On the committed extract at this head, the pooled line of `togi-tool-fit`'s forward-chained check prints the Go tool's to the digit (`log_loss/trial fit=0.6089`, `flagged/eligible=13/23`, `failures_p<0.01=88`); `target-fit-0` reaches negative log likelihood 209.517088 and the anchor 283.79098647702926, both the committed values. ## Stage 7: `tools/stats` (#820, 2026-10-12)

The `togi-tool-stats` crate ports `tools/stats` ([#820](https://github.com/shgew/togi/issues/820)): `togi-tool-stats [--state-dir DIR | --journal FILE] [--since TIME]` prints the review report of a current or archived journal, and `--forecast FILE` scores the run in `--state-dir` against a forecast instead. The library is `Journal::read` (or `Journal::new` over events), `report(&Journal, since)` and `score(state_dir, forecast)`, each returning the text; `main.rs` is the clap parser, the stdout write and the exit statuses (0, 1 with `togi-tool-stats: <error>` on stderr, 2 on a usage error). `just stats-rs` runs it next to the Go `stats` recipe, which is unchanged.

- **Design calls.**
  - It projects the journal's events directly (`togi-journal`'s `Recording`, so an unfinished last line is ignored and a journal that does not follow itself is an error). It does not use `togi-facts`, which validates what a tuning session needs (one decisive end per trial, a signal on every failure) and clones every event to do it; a review tool over a damaged journal should still report. `togi-facts` is not a dependency, against the Go package's import of `internal/facts`.
  - It reads no trial samples. A Rust `trial.end` carries the request telemetry the session summarized from the samples when it ended the trial, after a crash too, so Go's recovery of telemetry for ruleset-8 ends has nothing left to do. `togi-requests` supplies the top request; `togi-tuner` supplies `Profile` and `Topology` for the depth comparisons the evidence check needs, in place of `tuner.AtLeastDeep`.
  - The report is built as one string and written once, so a failed write is one error and exit status 1 and never a half report; Go kept the first write error of a section-by-section stream.
  - Tables are grouped by the vocabulary's own order (`R1`..`R7`, the activities and outcomes as declared), not by the alphabetical order of Go's strings. The Time table groups by the trial's activity, which replaces Go's phase. The R7 backoff report lists every backoff of a multi-core R7 failure: the Go ruleset-9 gate is gone with the Go rulesets. Legacy fallbacks for journals older than the profile and the cores of an intent (an absent profile, an R6 or R7 trial with no cores loading every core) are gone with the Go journals.
  - Goldens are insta snapshots of journals the tests build, so a tuner change leaves them alone; two tests over a simulated hunting session (cores 1 and 3 crash together) check the report against the journal's own events, not against bytes.
- **Go bugs fixed.** Go listed rulesets sorted as strings, so ruleset 10 sorted before 5; Rust sorts numerically (`rulesets_are_listed_in_numeric_order_and_builds_by_name`). Go printed an empty cell for the regime of a failure that names neither a regime nor a trial; Rust prints `-` (`a_failure_that_names_neither_a_regime_nor_a_trial_shows_dashes`). Go printed an inconclusive trial's reason raw, so a multi-line reason broke the table; Rust escapes it (`a_combination_failure_is_reported_in_every_section`) and prints `-` when there is none (`an_inconclusive_trial_without_a_reason_shows_a_dash`). Go sorted trial classes by their label text, so `120s` listed before `60s`; Rust orders them by catalog workload, loaded cores and numeric duration (`class_tables_list_workloads_in_catalog_order_and_durations_numerically`, `r7_request_tables_list_durations_numerically`), and prints hunt and cycle numbers unpadded.
- **Spec.** `docs/reviewing.md` gains "The Rust tool" with every difference from the Go output above; the Go text is unchanged until stage 9.
- **Tests.** 57 tests (the unit tests, 9 over the binary and a simulated session) run in about 1.0 s wall under `cargo nextest run -p togi-tool-stats`, against 0.2 s for `go test -count=1 ./tools/stats` (27 tests). Library 2,167 lines and tests 2,934 lines plus 575 of snapshots, against Go's 1,487 and 1,073.
- **Not measured.** Compile times against Go, agent cost, and the run on a Mac (the crate is clippy-clean for `aarch64-apple-darwin` from Linux).

## Stage 7: `cmd/togi` argument parsing, exits, version and completion (#825, 2026-10-12)

The `togi` crate (package `togi`, binary `togi`, library `togi_cli`) is the first of the four pull requests for `cmd/togi` ([#825](https://github.com/shgew/togi/issues/825)). It holds the clap parser, the typed exit statuses, `--version` and `togi completion bash|zsh|fish|nushell`; the other commands are not stubbed and arrive with the pull requests that implement them ([#826](https://github.com/shgew/togi/issues/826), [#828](https://github.com/shgew/togi/issues/828), [#829](https://github.com/shgew/togi/issues/829)). The crate's docs say how: one `Args` struct in a module, one `Command` variant and one arm of `Command::run`.

- **Design calls.**
  - `Exit` is one enum with a value for each status of the spec's table, including the doctor and dead-end codes 10 to 18, and `Exit::dead_end(DeadEndCondition)` is an exhaustive match. `main` is `run(args, stdout, stderr).into()`; `run` takes the streams as parameters, so the tests that call it directly cover the same code as the ones that run the binary.
  - `--state-dir` is `global = true` on the top-level parser, so every command takes it before or after its name. `--config` is `ConfigArgs`, flattened by `doctor`, `run` and `reset`; no other command has it. Go accepted `--config` before the command name too (`flags.go:30` registers it on the top-level flag set, `main.go:117` rejects it for a command that does not take it), and so does the spec; clap scopes a flag to its command, so `config_after_command` moves a leading `--config <path>` or `--config=<path>` to just after the command name before clap parses, and an unknown `--config` anywhere, with a command or without one, gets the spec's usage error `--config applies only to doctor, run and reset` (exit 2) in place of clap's unexpected-argument text.
  - A parse error is rendered by `clap::Error::render` and written by `run`, not printed by clap, so the exit status is `Exit::Usage` or `Exit::Ok` from the same enum and a failed write of the output is an error. clap's help, `-h`, `-V` and `help <command>` are kept as clap has them.
  - Flags without a command: `togi --state-dir /x` is clap's `MissingSubcommand`, which `report` words as the no-argument case (the wordmark and clap's help on stderr, exit 2), as the spec says `togi` without a command does; `togi --config x` stays the scope error. The command position for that error comes from the same scan that moves `--config` (`split_leading`), so a value of `--config` or `--state-dir` that is also a command name (`togi --config completion`) is not taken for the command.
  - The scripts come from `clap_complete` and `clap_complete_nushell`, written to stdout in one piece. The shells are an own `ValueEnum` of the four the spec names; clap's elvish and PowerShell are not offered.
  - The nushell script is loaded with `nu` by one test, which fails when `nu` is not on `PATH` rather than passing without loading anything; the dev shell and the flake's `rust-nextest` check provide `nu`.
- **Go bugs fixed.** Go ignored every write error (`_, _ = io.WriteString(...)`), so a full stdout cut a completion script or the help short and still exited 0; Rust exits 1 with the error on stderr (`a_script_that_cannot_be_written_is_an_error_not_a_panic`, `help_that_cannot_be_written_is_an_error`, and over the binary on `/dev/full`, `a_stdout_that_cannot_be_written_exits_1_with_the_error_on_stderr`). A stdout closed when the process starts is not fixed: Rust's runtime reopens fd 1 on `/dev/null` before `main` (seen with `strace`: `poll` reports `POLLNVAL` for fd 1, then `openat("/dev/null")` returns 1), so the output is discarded and the status is 0, as in Go; the spec's `completion` row says so. `deadEndExit` returned 1 for a condition it did not list, so a new dead end would have exited as a plain error without a test failing; the Rust match has no default arm, so a new `DeadEndCondition` does not compile until it has a status.
- **Spec.** `docs/spec/runtime.md` (the `completion` row and Shared flags, not the `--config` placement, which is as the spec has it): clap's error text and usage hint in place of Go's `flag provided but not defined` text; `-h` and `-V`; `help <command>`; the revision from `TOGI_REV`, with no VCS stamping, set by the flake's Rust package once it exists ([#830](https://github.com/shgew/togi/issues/830)) while `packages.default` stays the Go build with its own stamp; `togi` with only `--state-dir` prints the wordmark, and `--config` without a command is the scope error even with `--help` or `--version`; a failed write is exit 1 and a stdout closed at start is discarded with exit 0; completion generated from the clap definition, so it offers `-h` and `-V` and the shell names, bash completes a flag's value only after a space, and the comma-separated kinds of `events --kind` arrive with `events` ([#826](https://github.com/shgew/togi/issues/826)).

## Stage 6: the watch terminal loop (#836, 2026-10-12)

The `terminal` module of `togi-watch` ports the loop of `internal/watch` ([#836](https://github.com/shgew/togi/issues/836), part of [#641](https://github.com/shgew/togi/issues/641)): `terminal::run` and `terminal::run_after` show the live dashboard, `terminal::one_frame` prints one frame without a terminal, and the source, notification, key decoding, signals and `TERM=linux` palette are its private modules. Each public call drives its own current-thread tokio runtime and returns with no task and no thread still running. The loop is generic over a frame callback, so it is tested with fake frames and a recording ratatui backend under tokio's paused time; the frames of [#835](https://github.com/shgew/togi/issues/835) are composed with it in their own pull request.

- **What changed from Go.** ratatui diffs the buffer, so the row-diff writer, the per-row erase to end of line and the stale-row blanking are gone; the screen is cleared on entry and again on a resize or a view change, and the last row and column are never written (`docs/spec/runtime.md`, Dashboard, now says that). The journal is reloaded by file identity as before, but an append folds only its new events into the same model, and only while the last event the model folded is still in its place; a replacement, a truncation, a rewrite in place or a changed modification time at the same size builds a fresh one. The held log list is discarded on removal, replacement, truncation, a rewrite in place or a read error. A journal of a newer schema is a problem, judged with `Build::verdict` for `Operation::Inspect`. One queue carries keys, signals, resizes, journal changes and cancellation, so the loop reacts in the order things happened. SIGINT, SIGTERM and SIGHUP are installed by `run` itself (in Go, `cmd/togi` installed them); `Stop` lets another thread end a running dashboard, for the dashboard of `togi run`.
- **Go bugs fixed.** One, in the inotify adapter: the climb toward a missing state directory watches the first directory above it that exists, and a directory made between the failed watch below and that watch made no event anyone saw, so a `togi watch` started before its state directory chain was created could wait forever. The climb now looks again at the directory it last found missing once it has watched the one above, and climbs again if it now exists, at most once a level; `notify::linux::a_directory_made_while_the_climb_passes_it_is_still_watched` makes it between the two calls. Differences that are not bugs: a lone escape waits 50 ms of silence for the rest of a sequence, where Go anchored the 50 ms to the first fragment; the console palette is set only for the `Colours::Console` profile, so `TERM=linux` with `NO_COLOR` no longer redefines colours it will not use; the colour profile reads `TERM` only for `linux`, so `TERM=dumb` or an unset `TERM` no longer turns colour off as Go's colorprofile did, and only a non-empty `NO_COLOR` (or journald) does. The colour profile choice and the Linux console's colour table live in `terminal::palette`.
- **Notification.** inotify is used through `rustix` and tokio's `AsyncFd`, not the `notify` crate the issue names. The crate's mask includes `IN_OPEN`, which every reload of the journal would trigger, and its watcher thread is detached on drop, which the rule that each call returns with no thread still running rules out; the Go rules (watch the state directory and its parent, the journal alone when the directory is traverse-only, the nearest existing ancestor while it is missing, a once-a-second look only when nothing can be watched, one reload acknowledgement per change) are ported as they were. Nothing is looked for while the frame on screen is frozen. The non-Linux adapter polls once a second, also while frozen, because that is the only way it learns of a change.
- **Signals.** The dashboard listens through `tokio::signal`: `run` for SIGINT, SIGTERM, SIGHUP and SIGWINCH, and `run_after`, the dashboard of `togi run` (Go's `RunAfter`), for SIGWINCH only, taking its cancellation from a `Stop` handle. tokio cannot unregister a listener, so the listeners `run` made stay registered for the rest of the process: a later SIGINT, SIGTERM or SIGHUP no longer takes its default action, and SIGWINCH, which is ignored by default, behaves as before. Every command that shows the dashboard therefore keeps its own listener for SIGINT, SIGTERM and SIGHUP for the process's lifetime, as Go's `togi run` does through `signal.NotifyContext`. The owner decided this over `sigaction` handlers put back on exit, because those need `unsafe`, which the project allows only in the crates for `internal/trial` and `internal/hardware`. Two dashboards in one process both receive a signal, so neither waits for the other. The keyboard pipe is made close-on-exec in one call (`pipe2`) except on Apple platforms, which lack it.
- **Tests.** 101 unit tests (the loop under paused time with a recording backend, the reader on scripted and real pipes, the source on real files, the notifier with a fake watch under paused time, inotify on real directories, signals sent to the test process) and 22 `real_process_` tests, 19 of which run this test binary again on a pseudo-terminal: SIGINT, SIGTERM, SIGHUP and SIGWINCH on a frozen frame, keys, keys that are not a terminal, a SIGINT after `run` returns that neither kills the helper nor escapes a listener the helper makes afterwards, a second `run` in the process still ended by SIGINT, `run_after` leaving SIGINT, SIGTERM and SIGHUP to its caller's listeners, and real inotify through a running dashboard. The helper is killed on every path, and every wait is bounded: a helper must close its terminal within 30 s, a real pipe must deliver within 5 s, and a unit test waiting on a signal stops its dashboard or fails after 20 s. A wait on the pseudo-terminal resumes just past what it matched, so a frame that arrives in the same read as a marker is not skipped.
- **Review findings fixed.** Round 1 found 9 P2 and 16 P3 findings, all owned by the pull request. One P2 was a code defect: a journal rewritten in place to a longer one folded its tail onto the old model and kept the held log list. The other P2 were tests that passed without the code they named (the held-list drops on truncation and on a broken journal, the frozen notifier, stale-cell erasure, a repaint caused by SIGWINCH rather than the clock), a real-pipe test that raced the 50 ms escape timeout, helper waits that ended silently at their bound, and the unrecorded `unsafe` of the `sigaction` handlers, which the owner resolved by moving to `tokio::signal`. The P3 included the IN_Q_OVERFLOW path, the unreadable-ancestor rule, the pipes' close-on-exec race, tokio's then-unused `signal` feature, chmod tests that left unlistable directories on failure, the spec's palette sentence, and a second dashboard in the process that put the terminal into raw mode, flushing the first one's input, before it waited for the signals; that wait went with the `sigaction` handlers. ## Stage 7: `cmd/togi` reset, restart-limit and doctor (#828, 2026-10-12)

The `togi` crate gains the three administration commands ([#828](https://github.com/shgew/togi/issues/828)): `reset --core N | --all`, `restart-limit --tuning-boot <grubenv>` and `doctor`, one module each (`reset.rs`, `restart_limit.rs`, `doctor.rs`), one variant and one arm in `cli.rs`.

- **Design calls.**
  - **The host seam.** `system::System` is the one way a command reaches the machine: platform, privileges, host lock path and ownership, boot id, clock, the hardware diagnosis, GRUB, the retry marker, the reboot and what colours stderr. `Real` is the host and `togi_cli::run` uses it; `togi_cli::run_with` takes any other, so a Linux test stands for another platform, holds the host lock on a temporary file or answers the diagnosis without touching hardware. `run` ([#829](https://github.com/shgew/togi/issues/829)) adds its own methods to the same trait. It is documented in the crate docs.
  - **Unsupported platforms** ([#642](https://github.com/shgew/togi/issues/642)). `doctor` asks `check_platform` before it reads the journal or the configuration, takes the host lock or makes a check: `togi doctor: hardware runs need Linux: unsupported operation`, exit 1. The test gives it a journal `run` would refuse (it would be 16), a held host lock (3), a missing explicit configuration (2) and a state directory that does not exist, and checks that the state directory is not created, the lock file does not appear and the diagnosis is never called. The spec's doctor order is changed to match (below). `reset` has no platform check: Darwin resets a copied journal under a private lock (spec, Host lock), and `System::host_lock` returns `Policy::Private` there.
  - **No hardware in tests.** `doctor` reaches `togi_hardware::diagnose` only through `System::diagnose`; the tests answer it with a `Diagnosis`, so every doctor exit code is reachable without root, a driver or a Zen CPU. The tests over the real binary stop before it: usage errors, a refused or unreadable journal and a bad configuration all exit before the lock and the diagnosis. The retry marker, GRUB and the reboot are fakes too, so no test writes `/run`, `grubenv` or reboots.
  - **A journal's build is read without a lock.** `doctor` judges the journal from its first line (`recorded_build`, the read-only twin of `StateDir::live_build`, one commit shared with [#826](https://github.com/shgew/togi/issues/826)), so a newer schema exits 16 even when its later events cannot be decoded, and an older one, which `run` would archive, has no session to compare. `reset --core` does the same under the writer lock before it opens the journal, since opening would decode and repair it.
  - **`reset --all` has three shapes**, chosen by the first line: a journal of another schema is archived unread (`archive_unreadable`); one of this schema, whatever its ruleset or epoch, gets `command.reset` and is archived by `togi_session::reset_all`; a state directory without a live journal drops a pending carry or finishes an interrupted incompatible archive (`StateDir::open` completes the pending move, `close` releases it) and says which. All three leave the permanent `-reset-all` marker. The check for "no journal" runs before the locks and creates nothing; the one exception, a pending marker in `archive/`, is found by listing the directory, so a state directory named like a glob pattern works.
  - `reset` takes the host lock, then the boot id, then the writer lock: a busy host lock and a held writer lock are both exit 3 and leave the session as it was. A core number is a `u8` to clap; a core in range that the session lacks is `CommandError::NoSuchCore`, exit 2.
  - `doctor` prints the table itself (columns two spaces apart, details escaped), and the `not ready` line on stderr is `Style::RedBold` through the renderer, so `NO_COLOR`, the terminal and journald decide as for the other commands.
  - **Errors are escaped in one place.** `report::fail` and `report::exit_with` write `togi <command>: <message>` through `escape_text`, so no command prints an untrusted path or error text raw.
- **Go bugs fixed.** `reset` and `doctor` ignored a failed write to stdout (`fmt.Fprintf` results dropped), so a closed stdout still exited 0 with the message lost; Rust exits 1 (`a_closed_stdout_is_an_error` for both). `doctor` made its journal and configuration checks before the platform check, so on another platform it read the journal and could exit 16 or 2 before saying it cannot run (the order is #642's decision, below).
- **Native changes.** `reset --core` appends one `command.reset` and no `shutdown` (journal.md, Reset commands; Go appended one). `--core -1` and `--core 300` are clap usage errors, not a custom message. A journal of a newer schema, ruleset or evidence epoch, or holding an event kind this build does not know, exits 16 from `reset` and `doctor` with Go's text (`report::refusal_message`, `report::unknown_kind_message`, pinned verbatim by tests); the unknown kind comes from the journal's typed `ReadError::UnknownKind`, which `reset` and `doctor` match instead of Go's pre-scan of the kinds, and `reset --all` makes that check before it drops a pending carry. Messages that come from a Rust library keep that library's text where Go's wording was the operating system's or Go's: a configuration that cannot be read (`cannot read config <path>: No such file or directory (os error 2)`), a host lock that cannot be opened, a reboot that cannot run (`systemctl reboot: run systemctl reboot: ...`), and the `(os error N)` suffix of an I/O error in a marker path (`create retry marker: open /run/togi-retry-tuning-boot: ...`). `reset` logs in the local time zone (jiff's `tz-system`); a malformed first line (no `schema` stamp) is a decode error, exit 1, where Go read the missing stamp as schema 0 and exited 16. One workaround waits on an API: finishing an interrupted incompatible archive goes through `StateDir::open_at`, which creates an empty `events.jsonl`; `reset` removes it when it is empty, until `togi-journal` can recover the pending archive without opening a journal.
- **Spec.** `docs/spec/runtime.md`: the `doctor` row (the platform check comes first, before the journal and the configuration) and the Reset and compatibility section (`reset --core` appends no `shutdown`, as journal.md says); the stale statements to the contrary in runtime.md (Dashboard) and journal.md (rule 5) are removed.

## Stage 7: `cmd/togi` run, dashboard and panics (#829, 2026-10-12)

The `togi` crate gains `togi run` ([#829](https://github.com/shgew/togi/issues/829), the last of the four `cmd/togi` pull requests of [#642](https://github.com/shgew/togi/issues/642)): `run.rs` and its `outcome` and `prompt` modules, `signals.rs`, `panics.rs` and `dashboard.rs`. `togi-session` hands a panic back (`Ended.panic`, `Panic`, `SessionError::Panicked`) and `togi-journal` names an unknown kind (`ReadError::UnknownKind`).

- **Design calls.**
  - **The order of a run** is [#642](https://github.com/shgew/togi/issues/642)'s, platform first: the platform check (exit 1 before the state directory exists, the boot id, the journal or the host lock), the journal's writer lock (held: 3), the build verdict (a refusal appends nothing and exits 16; in the tuning boot it writes the leave reason and clears the saved entry under the host lock), the configuration (2), the process's signal listener, the host lock (busy: 3), the boot id, the hardware, the carry, then the session. `the_host_lock_is_taken_before_the_boot_id_is_read_and_the_hardware_opened` pins the order against the `System` seam.
  - **The run owner is the session.** `togi_session::run` owns the cleanup of every exit once the host lock and the hardware are held. The binary prints the outcome and maps it to a status (`run::outcome`), closes the journal, drops the host lock and, only then, reboots when the tuning boot asked for it.
  - **Signals.** One process-lifetime thread (`togi-signals`, a current-thread tokio runtime) turns SIGINT, SIGTERM and SIGHUP into the cancellation of every registered run. The dashboard never puts the input in raw mode (`keys: None`), so Ctrl-C stays a signal.
  - **Quiet input.** While the dashboard shows, `QuietInput` clears only `ECHO` and `ICANON`; `ISIG` stays. Giving the input back restores the flags with `TCSAFLUSH`, which drops what was typed during the run, and the defect prompt flushes with `TCIFLUSH` (`discard_typed_ahead`).
  - **The dashboard is drawn by `togi-watch`** on its own thread behind the `Surface` seam; its failure or panic is contained (`panics::contained`), `run` says `togi run: dashboard: <message>; printing events instead` and the session goes on (#398). Event lines are dropped only while it shows (`Gate`), and what the session reports while it shows is printed after it stops.
  - **Panics.** `panics::install` sets the hook. A panic on the owner thread after the hardware is set up runs the owner's cleanup (cancel, joined teardown, the offsets restored through the Smu seam, `ProfileRestored` recorded), then the dashboard stops, the journal closes, the host lock drops, and the process exits 2 with `panic: <message> (location)`. A panic on any other thread or tokio task prints the line and exits 2 at once; one before the host lock exits 2 with no lock and no events. The panic tests re-execute the test binary with a scenario in the environment and wrap the `Machine` through `Fake::wrap`; there is no fault-injection feature in the binary.
  - **The `System` seam** is #828's (`system.rs`, `report.rs`, `ConfigArgs::load`); `run` adds `open_machine`, `interactive`, `stderr` and `surface`. Every test of `run` runs on `Fake` in this process; the signal, pseudo-terminal and panic tests send their own process a signal or re-execute it, so they need nextest (a process per test).
  - **Sync only for `run` and `reset`.** `run` locks its state directory with `StateDir::lock` (fsync per event). `StateDir::lock_unsynced` is a `disallowed-methods` entry of `clippy.toml` with a single `#[expect]` in `togi-simrun`, so a use in the `togi` crate fails `just lint`; no further guard was added.
  - **Platform targets.** `togi` has no `cfg(target_os)` in its sources; the command surface, the help and the completions are the same on every target (`clippy --target aarch64-apple-darwin -p togi` is clean, and the run help and the completions are snapshots). Only `togi-hostlock::DEFAULT_PATH` differs per target, and `run` asks `System::host_lock` for it. The tests that need Linux (`doctor` past the platform check, `/dev/full`) are gated in the test files.
- **Go bugs fixed.**
  - A session panic left the offsets applied, the journal open and the host lock held (Go had only defers, no `recover`); Rust restores, closes, unlocks and then exits 2 with `panic:`. The Go test `TestRunOwnerEveryExit` had no panic mode; its row in `docs/rust-migration-stage-4-tests.md` is corrected.
  - Go read the journal before the platform check in `run`, as in `doctor`; the platform check is first now (runtime.md changed).
- **Native changes.** A panic ends with one `panic: <message> (location)` line and exit 2. `--cycles` takes `allow_negative_numbers`, so `-1` reaches the "must be a positive integer" message instead of being read as a flag. An unknown event kind is `ReadError::UnknownKind { line, kind }` (message `line N: unknown event kind "x"`), not a decode error, so `run` can name the kind: a current journal with one exits 16 before the configuration, an older one is archived (the configuration is read first and can still exit 2).
- **Spec.** `docs/spec/runtime.md`: the Run recovery line (platform first), the dashboard paragraph (quiet input, the panic fallback), the panic paragraph and exit row 2.
